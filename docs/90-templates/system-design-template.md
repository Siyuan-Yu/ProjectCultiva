# 系统设计模板

> 用法：复制本文件到 `docs/20-systems/`，重命名为 `2X-系统名.md`。
> 规则：**这份文档写不清楚，就不要开始写代码。**

---

# 系统名：`XXX`

- 状态：草稿 / 已定稿 / 已实现 / 已废弃
- 优先级：P0（垂直切片必需）/ P1（首发需要）/ P2（默认不做）
- 最后更新：`YYYY-MM-DD`
- 相关：`[链接到其他系统文档 / ADR]`

## 1. 这个系统解决什么问题

一句话说明它为玩家体验贡献了什么。**如果说不出来，这个系统就不该存在。**

## 2. 玩家视角

玩家在什么时候接触到它？看到什么？做什么决策？决策的取舍是什么（放弃什么才能得到什么）？

没有取舍的系统只是流程，不是玩法。

## 3. 规则定义

- 输入：依赖哪些数据/其他系统
- 规则：核心公式与判定逻辑，写清楚边界情况
- 输出：产生什么结果，影响哪些系统

## 4. 数据结构

需要哪些配置表、字段、类型、取值范围。字段命名必须与 `docs/00-project/03-glossary.md` 一致。

## 5. 数值与曲线

关键数值的取值与增长曲线，以及**为什么是这个值**（可附表格或图）。

## 6. 边界与异常

- 数值溢出、除零、空数据怎么处理
- 存档中途改配置表怎么办
- 玩家钻空子的路径有哪些

## 7. 与竞品的差异

对应 `14-borrow-and-differentiate.md` 中的哪条借鉴或差异化假设。

## 8. 验证方式

怎么判断这个系统做对了？列出可测试的断言（优先能写成单元测试的）。

## 9. 未决问题

- [ ] `[列出还没想清楚的点]`
