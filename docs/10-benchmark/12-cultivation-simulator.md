# 竞品拆解：了不起的修仙模拟器（Amazing Cultivation Simulator）

> 状态：初稿 | 最后更新：2026-07-29
> 用途：拆出可复用的系统结构。标注 `[需验证]` 的条目请实机确认后修正。

## 1. 一句话定位

类 RimWorld 的宗门经营模拟器：玩家不是修仙者，而是宗门背后的"天意"，通过**建造布局**、**弟子调度**和**系统嵌套**让整个宗门走向飞升。

## 2. 核心循环

```
选址开宗 → 规划建造（灵气/风水/阵法） → 招收弟子 → 分配工作与修行路线
   → 应对事件（妖兽、魔道、天灾、心魔） → 产出丹药法器提升弟子境界
   → 宗门整体上台阶 → 冲击更高目标（剧情/飞升）
```

核心张力：**资源与时间永远不够**。每个弟子既是劳动力又是修行者，玩家在"发展生产"与"提升境界"之间持续做取舍。

## 3. 系统清单

| 系统 | 作用 | 关键机制 |
|---|---|---|
| 弟子模拟 | 涌现故事来源 | 灵根（五行数值）、悟性、心性、特质、需求（食/眠/心情）、自主 AI 行为 |
| 工作调度 | 玩家主要操作面 | 工作优先级矩阵，AI 自行寻路取活 |
| 建造与布局 | 空间策略层 | 房间功能、灵气流动与聚集、风水加成、阵法 |
| 修炼 | 纵向进度 | 功法需匹配灵根，五行生克，打坐吸灵气，突破，走火入魔 |
| 心魔/内景 | 风险机制 | 修行失败进入心魔，需以另一套规则处理 |
| 生产链 | 资源转化 | 采集 → 炼丹/炼器/符箓/阵法 → 装备弟子或交易 |
| 事件 | 外部压力 | 妖兽袭击、魔道入侵、天灾、访客、剧情线 |
| 死亡与转世 | 长线连续性 | 弟子可死，可转世延续 |
| 数据驱动 | 内容可扩展 | 大量配置表 + 脚本/Mod 支持 `[需验证具体方案]` |

## 4. 它做对了什么（值得借鉴）

1. **涌现式叙事**：故事不是写出来的，是系统碰撞出来的。"某弟子因心性差走火入魔，连累整个丹房"这种事件是玩家自己讲给别人听的，内容成本近乎为零。
2. **五行生克贯穿全局**：一套元素规则同时驱动灵根、功法、丹药、阵法、克制关系。**一套规则复用到五个系统**，是小团队做深度的标准手法。
3. **空间即策略**：把"布局"变成核心决策，用美术量极低的俯视 2D 换来极高的策略深度。
4. **数据驱动架构**：内容与代码分离，让后期扩展和交接成本大幅降低。这一点直接对应你"可能交给别人做"的需求。
5. **群体单位替代精细动画**：弟子是小人偶，不需要动作手感，回避了动作游戏的重资产陷阱。

## 5. 它的问题（我们要避开）

1. **上手门槛高**：术语密集、UI 信息量大、缺乏渐进引导，新手前两小时极易流失。
2. **后期微操疲劳**：弟子数量上去后玩家变成"管保姆"，操作量线性膨胀而乐趣不增。
3. **目标感偏弱**：中期容易陷入"我在忙但不知道在追什么"。
4. **性能压力**：单位数与模拟粒度上去后帧率下滑，模拟型游戏的通病。
5. **可读性差**：系统之间的因果链不透明，玩家常不知道自己为什么失败。

## 6. 对我们的成本提示

| 部分 | 成本 | 备注 |
|---|---|---|
| 俯视 2D 表现 | 低 | 图块 + 简单单位，个人可控 |
| 弟子 AI（需求 + 工作调度） | 中高 | 是这类游戏最大的工程量，但一次做好可长期复用 |
| 建造/网格系统 | 中 | 有成熟方案可参考 |
| 五行与配置表 | 低 | 纯数据设计 |
| 大量 UI | 中高 | 模拟游戏的隐藏成本大头，容易被低估 |
