### 人工试玩建议（不是必须执行的游戏教程）

1. 新开局确认两人同行、同伴乙在监狱；查看左下状态。先做一次短工，分别给主角／同行者吃私粮，再探视送饭。
2. 趁原巡卫离开村门后，采木三次够搭棚；比较两处位置，在所选位置行动。看到实体棚／床，进入棚里存取各一份物资、休息、吃饭后修炼；村内尝试修炼应给明确拒绝原因。
3. 任选一种救援路线，观察是否保留伤势与位置；另一次开局可放任恶化、送药干预。不要用高倍速空等结果代替节奏体验。
4. 搭棚后、动作进行中、救人后分别手动存读档，检查床／库存／角色状态／动作时长不重置，配给不会刷新，同伴不会再次被囚或复活。
5. 后续仍用已有战斗与议政厅攻占方式取得荒村；营救和搭棚都不应成为隐藏门槛。

### 持久化与接线

Core `HuangcunSurvivalState/Service`＋`HuangcunSurvivalAction`，OrderType仅追加10；在实际Tick驱动囚禁饥饿和生命损耗。Host只发订单／导航请求，初始队伍在既有Squad服务中播种，不放宽普通入队的同场要求。配给日额度使用既有计数／每日标记，物资仍在公库、背包或独立私人库存；动作完成时复核。Snapshot保存场景、精确候选点、产权、库存、释放状态及活动ActionClock；身体与位置仍在原实体和WorldPresence。v15-v18格式兼容与内容版本兼容是两回事；旧存档不被静默套上本轮规则。

### 明确未包含

近／远营地首版区别为地理路程，尚无独立“被搜查概率”、伪装或告密后果；潜修继续利用既有个人隐匿风险／巡卫出村门禁。不是完整饥荒系统：没有烹饪／天气／自由铺房／完整丹器制作树。采集与赎人目前是现场计时交互、提示和真实资源结算，不是完整角色动画与分支对话演出。伙伴自动分工、囚禁剧情演出、长期劳动压迫与正常成长节奏仍需后续打磨，不能宣称一次实现就达到原体验预期。

### 本轮检查

仅四程序集基础编译及少量JSON／引用／文件完整性静态检查；未启动Unity，未编写或运行自动测试，未进行实际画面或存档往返验收。游戏内体验仍由制作人验收。

## 已确认的体验与规则

### 配给只能维持生活

- 初始三人均受配给限制，不只限制当前主控；切换主控、加入／离开同行或读档不能刷新配给。
- 配给的日总营养量应覆盖正常生活的基础消耗，进食后仍处于低饱食区间，不能积累出持续修炼所需的余量。
- 配给和额外食物的差别必须有真实消耗与界面解释，不只是把同一份食物改名。具体份量先由现有消耗计算，再经正常开局人工调整，不在设计阶段冒充已平衡。
- 私人采集、交换和额外劳动所得可以储存，用于外出、同伴恢复或修炼。不能由宗主公库的现有共享权限绕过配给限制。
- 基本生计必须可恢复。缺勤可以导致警告、补工等轻量后果，但不能首次犯错就断绝一切食物来源；饥饿不能使玩家连安全采集也做不了。
- 日配给按 WorldTick 和真实人物结算；有明确领取地点／来源，不能人在远方仍凭空收到配给。暂停、加速、存读档都不得改变每日总额。

### 修炼消耗额外准备

- 修炼在基础生活消耗之外消耗身体余量；仅靠最低配给不能持续修炼。
- 开始前显示饱食／精力条件及预计消耗；不足时明确提示，修炼中耗至安全下限时停止，不扣已获得修为。
- 私人食物需要有明确的进食／准备入口，不能出现“背包有粮，却因自动进食阈值不同永远无法开始修炼”。
- 城内正式修炼设施开局不对劳役开放；野外可基础吐纳，简易修炼空间改善稳定性。设施权限与野外效率分别处理，不能仅在 UI 隐藏入口而 Core 仍绕过。
- 不更改飞行、地图尺度、境界阶梯和真实占领条件，不新增“完成教程才可突破／攻城”的门槛。

### 小型营地而非提前经营领地

- 地点限定荒村城墙外、已开放盆地内；不开放盆地外界、不创建 SiteCore／TerritoryClaim，不把临时棚屋算城镇。
- 第一阶段包含简易遮蔽处、修炼位置、私人储物和休息位置。使用真实材料、占地与交互，不用纯剧情旗标模拟完整建筑。
- 提供修复近处废棚或自行搭建隐蔽营地的选择；位置在路程、隐蔽性和资源可达性之间有区别，不强制固定顺序。
- 营地材料来源与实际建造入口必须一起交付，不能只开放建造按钮。
- 私人物资与据点公库相互独立；建造不凭空搬运远处库存。占村后保留既有营地与物资，不能自动丢失或被重新初始化。
- 后续简易加工、药材处理是小规模生活支持，不表示本轮要完成炼丹／炼器生产树。

### 同伴与恢复

- 保留单 Active、真实人物与现有小队控制规则；不扩展远程 RTS 操作。
- 让已有采集、休息、医疗与成长倾向产生实际分工价值，自动处理基础吃饭休息，玩家决定优先事项。
- 负伤可撤退、救助和休整，营地成为恢复后的再次出发点；不把永久劳动供养主角作为唯一有效策略。
- 开始阶段只围绕食物、精力、伤势、材料与修炼准备，不同时增加口渴、体温、精神值、复杂腐败等新需求。

### 轻量巡查和人情事件

- 风险来自真实缺勤、近场目击和可理解的巡逻时段；现有 PersonalConcealmentRisk 不能直接充当全知的营地发现或 NPC 怀疑。
- 先做警告／补工等有退路的后果，复杂搜查、追捕、告密和营地摧毁不作为首批实现要求。
- 少量事件围绕伤员用药、修缮余料、废棚选址、采药路线、资源点危险、余粮交换和换班消息展开。可忽略、有替代路线，不全部做完也能挑战议政厅。
- NPC 帮助应改变实际资源、路线信息或服务机会，而非只有关系数值；关系变更仍走 RelationshipLedger。
- 成长后逐渐减少同等劳动／风险所需成本，实际效果走现有属性管道，避免生存家务随流程永久等量累加。

## ACR 村外个人营地与私人储物

- 提出者：Development；制作人的玩法需求已确认，框架扩展待明确授权。
- 冲突：26 与 ADR-0032 的现行建设许可依赖实际行政控制；现有储藏室对应据点公库，尚无营地独立私人储物权威。仅放宽 Host 或伪绑定荒村 Site 会产生越权、公私混库和读档不一致。
- 建议：增加范围受限的非行政营地资产／使用许可，明确其建造者或小队产权、物理位置、设施关联及私人库存持久化；沿既有 Continuous Surface、资产 ID、Order／Action、Snapshot 体系接线，不恢复旧空间 authority。
- 数据边界：需要先确定并记录资产／容器字段、Snapshot 版本与旧档策略，再实施 Core、Data 和 Host；不更改既有稳定枚举值／ID，不修改 Freeze 历史正文。
- 旧档：新开局使用新生存规则；现有档默认不清空物资、不强制降饱食、不猜测新营地。若允许升级旧档，必须有显式版本转换和完整默认语义，不能重跑开局种子。
- 不纳入：新城镇创建、圈地扩张、公库远程取物、完整建筑产权交易、NPC 自主建营、复杂追捕及炼丹炼器配方。
- 获授权后：更新对应 ADR、25／26 的精确规则和存档契约，再一次接通下方实施顺序，不能将本 ACR 的提出写成已获架构批准。

## 单轮实施顺序与验收边界

1. 配给／私人食物、初始状态与修炼消耗；查询、实际扣除、自动吃饭和提示一致。
2. 安全采集与私人材料收益、营地建造／修复及私人储藏；建设和存读档一起接通。
3. 修炼点资格、营地使用、同伴恢复与少量人情事件；巡查只做已定义的轻量后果。
4. 正常开局人工体验：能靠配给勉强维持生活，能靠额外行动积攒修炼余量；获得第一个私人落脚点后，确实减少对村内供给的依赖。

执行期间只做基础编译与最少量静态引用／文件完整性检查，不启动 Unity、不编写或运行自动测试。配给平衡、第一次营地所需时间、失败后能否继续等由制作人正常开局人工验收，不能从代码存在推断体验已完成。不自动提交／推送。
