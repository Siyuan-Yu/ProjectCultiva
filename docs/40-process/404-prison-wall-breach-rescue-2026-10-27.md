# 404 — 监狱墙体破坏与就地解除拘押（2026-10-27）

状态：Design Confirmed / Implemented / Producer Acceptance Pending。

## 本轮唯一实施指令

按制作人确认，退役撬锁及“两名巡卫失能后点击强救”。正常右键监狱墙体走既有势力侵略预览、宣战确认及 CharacterEncounter；不得伪装成议政厅占领目标。攻击主管、议政厅或其他正常战争中的冻结战场，只要包含监狱墙体，也可正常破坏墙体。

## 规则

- 未宣战、非参战角色、错误 Surface 或冻结战场范围外不能伤害敌方监狱墙。惩戒战斗不等于势力战争。无可战守军时也沿用独立战场，不凭空生成敌人。
- 墙体沿用真实耐久与 OutdoorStatefulObjects 持久化；不是交互按钮直接删墙。未打穿、原有门洞、仅有伤害、仍被地形或其他实体堵住的缺口均不算营救成功。
- 导航更新后，确认被毁墙段上确有角色可穿过的内外连接，再对该牢房中的实际囚犯就地解除拘押。无额外“强救”按钮，不要求两名巡卫失能，不自动占领荒村。
- 解除拘押不搬动 exact WorldPosition，不恢复 HP、饱食、药量、昏迷/濒危与治疗状态，不自动加入玩家队伍。不把囚犯伪装成战斗参战者。清醒者此后可正常离开；昏迷者仍需治疗或搬运。战后返回及读档不得重新拘押或回床。
- 占领后的管理者“下令释放”保留；既有交涉赎人本轮不退役。修炼丹药不做。
- 旧存档中的 pick_lock 行动只作兼容识别，执行时明确取消，不扣材料、不放人。force_release 仅允许取得荒村后近身对人下令释放。

## 实现边界

Continuous Surface / Squad / CharacterEncounter authority 不变；不改 Freeze、稳定枚举或已有字段含义。无守军结构战以可选 PrisonAssaultRoomId 保存真实房间身份（旧存档缺省为空），复用普通参战名单与战场流程，不绑定 SiteCore 占领目标。墙体与囚犯复用既有持久化状态。

## 人工验收

实现说明：最终伤害入口也校验战争与冻结范围。囚犯作为非战斗旁观者按 exact WorldPosition 显示，清醒者解除拘押后通过既有移动意图寻路离开；昏迷者不发移动命令。返场／加载导航更新后依照既有持久化毁坏状态补判可通行缺口，避免墙已毁而提前离场导致永久漏放。已宣战双方不再套用残留惩戒身份。四程序集离线基础编译通过；未运行自动测试、未启动 Unity，未提交／推送。

1. 旧面板无撬锁或巡卫失能强救；旧行动不能继续放人。占领后对同伴下令释放仍有效。
2. 和平右键监狱墙需正常宣战确认；取消不伤墙。惩戒战及战场外墙不允许拆。宣战攻墙不自动占领议政厅；守军均失能时仍能进入结构战。
3. 只有形成可走缺口才自动解除拘押；未打穿及堵住的破口不放人。同一战场中攻击主管/议政厅时也能破墙营救。
4. 比较营救前后位置、HP、药量及昏迷状态；不瞬移、不痊愈、不自动入队。返回大地图、存读档后墙缺口和获救状态保留。
