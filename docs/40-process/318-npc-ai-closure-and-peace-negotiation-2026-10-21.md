# NPC AI 闭环与多轮停战谈判

> 状态：Design Confirmed / Implemented / Producer Acceptance Pending。2026-10-22 制作人授权将当前实施范围封板并提交上传；Git 结果以仓库记录为准，封板不等于本页逐项人工验收。主场景 `Assets/Scenes/LevelTester.unity`。本页补充并覆写 317 中对应的历史缺口，不代表全部 NPC AI 或所有内容已验收。

## 制作人确认的规则

- 玩家主动休息时全队一起休息；低精力不自行安排整队返床或打断行军。精力耗尽时本人原地躺下停止行动，恢复后继续；不改为受伤、弥留或死亡。
- 队员不自行离队寻找食物、不跨地点采购。现有共享背包就地进食保留；凡人队员也不远程扣驻地仓库。精力或饱食度很低时在队伍栏持续提醒。
- 停战谈判必须支持多轮还价。可以约定实际公库资源赔偿、要求我方或敌方释放其实际关押的俘虏、要求对方整个势力成为我方附庸。
- 正常自由人物不能成为交易对象；释放不等于招募或改变人物阵营。交付不新增押送过程。既有主动抓捕、住宅／牢房安置流程保留。
- 成交结束双方势力战争，而不是只结束一次交战。沿用现有绑定参战方的战争实体，结束包含双方对立阵营的战争及其参战方；不暗中转让据点、不宣告征服。

## 实际接线

### 生活、移动与战斗

- `NpcColdMovement` 统一离屏返床、蒲团和撤离的逐段移动预算；同一 WorldTick 两次 Drive 不重复花移动预算。保存实际位置、最后推进 Tick 和撤离目标，读档重新规划合法路线。
- 离屏局部寻路使用地表格、真实房间墙体／门洞、未拆毁墙格、床、仓库及墙段的逻辑几何。局部窗口最多 256×256 格；超范围或无路按受阻处理，不分配全世界地块对象。返床失败保底休息后重试。
- 离屏接敌距离改为 6 格，近战实际接触距离沿用 1.6 格尺度，必须先接近才能结算；不再以 3 个世界单位直接远距离互砍。现场与离屏均用合法格段作保守接触／遮挡检查。这不是独立的透明材质或视觉锥模型。
- 离屏撤离不直接写终点；现场户外撤离也保留可恢复的目标。Party／Squad／战斗等现有控制权继续优先，不让个人撤离抢夺活动小队的控制权。
- 六个斗技栏及普攻间隔保存在真实人物的 `NpcAutonomyState`；非独立现场冷却不再只存在 Host 字典。独立战场沿用原有 Encounter 冷却保存。暂停沿用既有 Session／表现时钟。
- 主动地面休息和床边休息通过 Core 入口安排全队休息。床边主控使用已到达且可用的指定床，其他成员在当前位置休息，不远程预占住宅床。既有搬运负担限制不取消。
- 当前实现默认：需求 ≤15 显示提醒；精力 0 进入强制卧倒，恢复到 ≥30 解除力竭。以上为可调整的实施初值，不改变医疗 HP 超过 50% 的苏醒规则。力竭不是生命失能；保留真实位置，不随队伍跨区投影移动。
- 普通显式休息可以由新的玩家移动指令中断；力竭期间不能借 WASD、点击移动、普通动作或攻击绕过休息。恢复后沿用原有职业／跟随职责。

### 多轮谈判

- 入口：世界地图的“势力／外交”，选择交战势力，点击“开始停战谈判”。当前交战或战报须先结束，避免直接覆盖战斗结算。
- 选择双方实际控制的有效公库地点及资源；数量为正表示对方赔我，为负表示我方支付，0 表示无资源赔偿。这里只接实际 Site 公库，不把个人灵石钱包当作新建的势力国库。
- 勾选实际俘虏释放名单，或要求对方势力附庸；提交后对方可以接受或提出反提案。修改条件可继续谈；修改任一字段使旧反提案失效，不能按旧承诺成交新条款。
- 反提案为确定性的当前力量／库存／对等释放评估，不以反复点击随机刷新结果。实施初值：力量为可战斗人物攻击值加当前 HP 的 0.1 倍；要求附庸需我方力量至少为对方 2 倍；不对等释放需至少 1.5 倍。可接受赔偿比例为 `(力量比−1)×0.25`，限制于库存的 0～75%。这些是待制作人验收调整的首版数值，不声称最终平衡。
- 成交前重新检查战争、附庸、联盟边界、库存数量与溢出、释放对象实际关押方及战斗锁。普通人和已经释放者不能通过重提／读档重复交付。
- 附庸复用 `VassalageBoard`，禁止套娃、转卖别人的附庸；成为附庸时退出其独立联盟。不改变人物阵营或据点所有权，既有直接附庸仓储权限动态生效。
- 释放清除实际关押与床位、旧押送和旅行责任；人物返回原阵营的一个有效地点，无合法地点则在当前真实位置自由。不建立押送动作、不治疗伤势、不新造人物、不自动加入我方。
- 签约停战关闭对应战争，清除签约双方显式私人先手敌对事实，保留关系历史与态度。已成交停战约束自动先手及残留近战伤害；重新正式宣战后可再战。

## 存档

- 保持现有 v17 数值，以可选字段追加人物自主状态和谈判记录，不静默删除或覆盖旧档。
- 本轮额外修复此前只进入 DTO、未进入 JSON wire 的个人需求／倾向／时间字段；完整链路为 Core Capture → DTO → JSON → DTO → Core Restore。
- 保存提案轮次、反提案、名单、资源条款、附庸条款及成交状态。记录深拷贝，读档不回放成交操作。实际库存、战争、附庸及关押状态继续由原有系统保存。
- 较旧客户端不保证保留新增字段，不建议将本轮存档交给旧客户端覆盖保存。

## 实际检查与人工验收

执行 `powershell -ExecutionPolicy Bypass -File tools/offline-compile.ps1`：8 个程序集离线编译通过。存在原有 CS0105／CS1718 警告。编译测试程序集不等于运行测试。遵循 AGENTS：未启动 Unity，未编写／运行自动测试、PlayMode、headless 或存档回放。以下均待制作人现场验收。

1. LevelTester 新开局，队伍移动中主动休息，所有可休息成员停止移动并卧倒；再次移动可中断普通休息。
2. 持续行动至低需求，核对队伍栏提醒；精力到 0 时该成员留在原地，WASD／点击／跟随／跨区不把他拉走，恢复到 30 后可行动。其余人不自行离队找粮。
3. 未入队居民疲劳返床时离开现场，再返回，确认仍有合理位置、返床或保底休息；保存读取再核对，不长期卡在“前往床铺”。
4. 隔墙放置敌对双方，核对自动发现、攻击与门洞；靠近离屏敌对 NPC 后来回加载，核对无远距扣血、无重复伤害、撤离不直接跳终点。
5. 非独立现场 NPC 使用斗技后保存读取，核对剩余冷却；暂停期间冷却及动作不推进。重复核对第 5／6 个技能栏。
6. 与交战势力谈判，提出资源／释放条件，查看反提案、修改并继续谈；自由人物不出现于名单。库存不足、俘虏已释放或附庸不合法时有明确拒绝。
7. 接受反提案后核对实际库存、人物原阵营及伤势、没有押送、双方战争结束且不继续互砍。独立之后可验收要求对方附庸及其联盟退出、仓储权限。
8. 分别在未成交反提案和成交后保存读取：轮次／条件保留，成交不重复扣资源或释放；原有工作、床位及医疗恢复继续正常。

本轮未修改 Content JSON、Prefab、场景、Packages、ProjectSettings 或旧 Hex／Army 系统。正式验收只使用 LevelTester。
