# 被囚同伴右键菜单入口返修

日期：2026-10-28。状态：Implemented / Producer Acceptance Pending。

## 单轮实施指令

制作人反馈右键牢内同伴乙没有对话菜单。HostNpcContextMenu先用IsPartyUnit排除了目标，但该查询按永久Character／玩家势力管理资格判断，并不等于当前在队且自由；被囚同伴仍带Character标记，因此尚未进入既有探视判断便被过滤，右键落入普通移动。

本轮仅修Host右键人物入口：有效牢房拘押人物优先于普通可控人物过滤，沿既有PrisonConfinementService查询，不按姓名或阵营猜测。原同伴乙探视与普通囚犯菜单、实际进房及三格距离、身体限制、巡视发现追赶、送饭送药和监管权限继续沿原规则。不扩大人物控制权，不解押、不入队、不改位置伤势或存档，不影响押送中俘虏的抱持者权限。

做基础离线编译及最少差异／引用检查，不启动Unity、不新增或运行自动测试、不提交推送；保留已有修改及地图备份。

## 人工验收

自由状态下右键主角／同伴甲仍保持原移动操作；右键牢内同伴乙应出现“与同伴乙对话”，距离不足显示原因。进入牢房靠近三格后、未被巡视发现时可进入探视，查看身体及送饭送药／任务正常；被巡视发现仍追赶开战。占领后普通拘押人物仍可打开对话／身体菜单，不因己方管理资格被过滤。释放后不再走囚犯菜单。

## 实施结果

HostNpcContextMenu已按上述优先级接线。Core／Data／Unity／Unity.Editor／Tests五程序集离线编译通过（仅编译，未执行测试），diff检查通过；两处已有无关测试源码警告保留。未启动Unity、未提交推送；现场行为待上述人工验收。
