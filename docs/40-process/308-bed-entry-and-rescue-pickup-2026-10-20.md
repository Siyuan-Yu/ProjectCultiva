# 上床过渡与救援接人衔接（2026-10-20）

状态：**Design Confirmed（制作人本轮明确要求）/ Implementation Complete / Producer Acceptance Pending / Committed·Sealed（2026-10-20）**。Host 离线基础编译通过；开发代理未启动 Unity 或运行自动测试。

制作人现场反馈：人物到床边后立即跳成床上卧姿，观感突兀；自动救援者在弥留者面前停留，期望到达旁边便立即抱起并出发去已选床位，不显示或引入接人读条。参考《环世界》“靠近目标—接人—送往床位”的连续动作节奏，仅借鉴观感，不复制资源或改变既有玩法。

实施边界：上床只在 Host 人物视觉子层做短时、可被唤醒/死亡/被搬运打断的床边至床上插值；人物 Core 坐标、床位占用、碰撞和存档真源不变。救援沿用现有 `RescueCarrying` 和床位预约；靠近伤员时使用已有接人距离作为导航到达半径，到达后在同次业务更新中切为搬运并发出送床意图，不增加 WorkTicks、ActionClock、读条或 Snapshot 字段。路径失败、床位失效继续按现有失败分支处理。

人工验收待制作人：安排普通居民睡床，观察到床边后短暂滑入床面，醒来后可正常走动；安排一名弥留者与可用医疗床，观察救援者到其旁边立即抱起并转向床位，不在伤员旁停顿读条；暂停、救援失败或床位变化时不应留下床上残影或悬空人物。

实施记录：模组骨骼与旧卧姿 Sprite 都在开始上床时以约 0.42 秒的缓动移动到床面；过渡期间人物绘制在被沿前方，结束后回到被沿下方。救援接近伤员以既有接人半径选合法旁边站位，不再要求踩到伤员中心格；Core 识别到达后立即写入 `RescueCarrying` 并同轮发起送床移动。没有新增进度或等待状态。模拟更新节奏及现有路径失败重试仍由原系统决定。

## 现场复看：被搬运者落在搬运者身后

制作人截图显示，往北送床时弥留者落在搬运者下方，看起来像被拖行。现有 `HostNpcScheduleMover.SyncCarriedCharacters` 对救援与押送统一使用固定世界偏移 `(-0.28, -0.16)`，不随搬运者朝向变化，且按被搬运者自身地面 Y 排序。返修只调整 Host 表现：被搬运者相对搬运者当前朝向置于身前，深度跟随搬运者并排在其身前；实际 WorldPresence 继续与搬运者同一世界点，救援、押送、床位和存档规则不变。人工验收补充：让救援者朝上、下、左、右行进，确认被搬运者都在行进方向的身前并随转向一起转，不再拖在背后；放到床后不保留搬运偏移。

返修已接线：Host 对被搬运 View 使用搬运者当前美术朝向的 0.38 表现单位前向偏移，并将其绘制顺序钉在搬运者之前。脱离搬运状态即恢复普通脚点排序。状态仍为 **Implementation Complete / Producer Acceptance Pending / Committed·Sealed（2026-10-20）**。

## 现场复看：睡眠 NPC 参战时仍保持卧姿

制作人截图显示 NPC 已标记“交战中”并攻击，但人物仍躺着。排查定位：`EntityView.IsSleeping` 和 `UpdateSleepVisual` 优先消费未及时清掉的 Civilian SleepPhase／BedRestAction，前者还直接阻止 `PlayArtAttack`。已明确本轮表现规则：处于 Active／ReadyToEnd 的正式 `CharacterEncounter` 参与者，只要仍可战斗，战斗站姿与攻击动画优先于睡眠 View；弥留、死亡者不因此站起。此处只处理 Host 表现与攻击动画门禁，Core 睡眠终止、床位占用和存档继续由既有系统管理。人工验收补充：睡着时主动开战，确认 NPC 第一段战斗即站立并在出招时播放攻击动作；非参战睡者仍保持卧姿，倒地者仍按生命状态显示。

返修已接线：`EntityView` 对正式交战中的存活参与者统一覆盖睡眠视觉判定，同时恢复真实攻击动画入口；仍以 Core 战斗阶段与参与者身份为判据，不用“交战中”文案推断。`XianXia.Unity` 离线基础编译通过，未启动 Unity 或运行自动测试。状态：**Implementation Complete / Producer Acceptance Pending / Committed·Sealed（2026-10-20）**。
