# 田地比例与议政厅封闭外观返修

> 状态：Design Confirmed / Implemented / Producer Acceptance Pending / Committed·Sealed｜2026-10-19

## 问题与目标

制作人现场截图显示麦田、药田像许多缩小的独立田块，固定议政厅则像圆形占点棋子。核查 Host 接线：田地的四阶段图本身是一整块带土边的方形田，每个逻辑作物格都被替换为这张完整方块；议政厅的 `controlCore` 使用圆形占点图，`ApplyObjectVisual` 又按逻辑占地的宽高分别拉伸。两者都把逻辑格尺寸当成了最终美术构图。

本轮让田地成为连续的耕种区，并把预设 Site 的议政厅表现为可辨识、封闭、有体量的建筑外观。参考《了不起的修仙模拟器》的俯视经营构图以及本项目黄村风格图，只借鉴建筑的屋顶、围护和入口层次，不复制其它游戏资源。议政厅不展示室内；固定 `SiteCore` 的身份和既有防御、攻破、接管交互仍由正式系统决定。

## 实施边界

- 只改 Unity Host 图片资源与视觉适配。保留田地每格的稳定 ID、作物阶段、生长/收获、点击框和导航。
- 田地阶段继续按各格真实状态区分；视觉尺寸不再把完整的“单块田”缩进每个逻辑格。具体用无边界作物切件与连续土地区域呈现，避免重复外框。
- `controlCore` 换成单张透明背景的封闭议政厅外观，按等比例缩放与地面脚印对齐，不再做横纵独立拉伸。保留原逻辑占地、碰撞/选中/接管、旗帜阵营映射。
- 制作人提到的对敌攻击属于新玩法规则和授权边界；本轮只记录为 Proposed，不在 Host 虚构伤害或攻击判定。
- 不改 Core／Data／Content、Freeze、ProjectSettings、Packages，不启动 Unity、不写或运行自动测试。基础离线编译与最少资源引用检查之后交制作人人工验收。

## 实际接线与验收

新图 `ART-ROOM-008_council_hall_closed_v04` 是封闭瓦顶木构议政厅；本轮后续制作人补充其应具备仙术攻击设施，故运行图改为在同一屋顶上增设小型符阵的 `ART-ROOM-008_council_hall_ward_v05`。两张候选、生成来源与 SHA 记录在 `ArtSource/Batches/Batch_CouncilHall_001/manifest.json`，旧圆形核心图保留为历史候选。`controlCore` 只在 Host 换图，按保持宽高比贴到原有 8×8 视觉框，并让建筑南端靠近原框底部；未触及 SiteCore authority。符阵目前仅为静态外观，不表示已经能自动攻击。攻击规则请求见 [301 ACR](301-acr-council-hall-spirit-defense-2026-10-18.md)。麦田／药田四阶段继续从原图集取图，但裁掉每张原图的独立土边，只展示内部连续垄沟和植株；原单格脚点、WorldRect 与真实生长状态不改。离线 `XianXia.Unity` 基础编译 `ALL_OK`。

制作人在 LevelTester 同一缩放下看：田地应读成整片连续耕地，四阶段与成熟/收获仍对应实际状态；议政厅应一眼看成封闭建筑而不是圆盘，缩放地图不出现横纵拉扁；点选/攻破/接管使用原有位置与逻辑。以上均待人工现场验收，编译结果不能替代。对敌自动攻击仍为 Proposed，须 Architecture/System Design 明确规则后另行实施。
