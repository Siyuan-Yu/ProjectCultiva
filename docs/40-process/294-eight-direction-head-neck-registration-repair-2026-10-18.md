# 八向头颈脱节返修：本轮实施与待验

> 2026-10-18｜Design Confirmed / Implemented / Producer Acceptance Pending / Not Committed。制作人在 LevelTester 截图指出主角四个斜向走路时头与躯干脱节；本轮只返修斜向四件图集的裁框与颈部注册，不改移动或玩法规则。

## 唯一实施指令

沿图集裁框、Sprite pivot、躯干 Socket 和左右镜像链路找斜向头身错位的可复现原因。对 12 套 HumanCommonRig Skin 的四斜向共用资产做相同修复；保留既有八扇区方向判定、步频、工具、睡眠闭眼与旧资源回退。只作基础编译和静态资源完整性核对，不启动 Unity、不写或运行自动测试；现场四斜向观感由制作人人工验收。

## 已查明的原因和改动

上一轮 `Batch_ModularRig_004` 导出器直接对任意非零 alpha 取外接框。生成图的空白边缘有接近透明的散点；主角斜后头像实际可见区域只占所声明 Sprite 高度约 68%，斜前约 86%，其他 Skin 的斜后头亦有约 70%～90% 的占比。`Sprite.Create` 仍按整个过大矩形和固定 `worldHeight=0.74` 缩放，固定 `pivotY=0.06` 又落在空白中，导致可见头变小、颈根被抬离衣领。过宽的躯干框还把肩部 Socket 推远，使手臂看起来向两边张开。此问题来自导出布局，不是寻路或走路状态没有接上。

`tools/export-human-rig-diagonal-layouts.py` 现按 alpha ≥ 16 定位四个真实画面部分，仍仅复制原 PNG、只改 Unity 布局 JSON。头部 `pivotX` 根据可见头像底部 10% 的形状中心确定，使不同发型与斜向颈根落在躯干 Socket，而不是所有人固定 `.54`。保留 2 像素安全边和原 `worldHeight`，原图与运行图字节不变，Unity `.meta` GUID 不变。主角斜后头像裁框由 552×610 收紧为 421×420；斜前由 544×544 收紧为 493×474。肩部仍用现有骨架和原工作/工具姿势。

## 核对与人工验收

静态核对 12 套原/运行图 SHA 一致、48 个新裁框均在对应四分格内、布局 JSON 可读且 `.meta` GUID 稳定；`XianXia.Unity` 基础编译 `ALL_OK`。没有 Unity 运行画面复核，制作人上一轮截图是真实失败证据，不能以离线检查覆盖它。

1. 主角右键依次走左下、右上、右下及左上：停住与迈步两相都看头发/下巴是否贴在衣领上，手臂不再横向张开；换向时不跳头。
2. 抽查阿石、阿土、阿禾、江老同样四斜向，并看拿工具时肩膀、手、工具是否仍相连。
3. 正、背、左右原四向及床上闭眼只需快速回归，确认未受本轮布局返修影响。
