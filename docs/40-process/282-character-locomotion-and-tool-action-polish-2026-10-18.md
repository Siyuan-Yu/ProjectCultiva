## 本轮唯一实施范围

制作人授权先完成 NPC 自主走路、主控右键移动的动画接线与表现，以及相关走停转向、工具动作和握持；整体以《了不起的修仙模拟器》式俯视经营镜头的清楚、连贯为标准。复用现有部件与工具，不批量生图。

本轮统一处理有效移动到动画的信号、默认视觉驱动与可见层、步态连续性、劳动关键姿态和工具挂点，以及范围内睡姿方向。定位发现与直接接线随本轮完成，不按人物或代码文件拆成多轮实施。

人物根节点、碰撞、Core 世界位置、导航、移动速度、伤害、产出、背包／正式装备与存档规则保持既有真源。宏观移动如需平滑只作用于视觉，不改真实位置与互动 authority。治疗、环境模块和整套正式装备不进入本轮。

## 本轮定位结论

没有找到右键与近场 NPC 两条磁盘调用链共同缺失 Walk 调用的证据。已确认的表现问题是：原正背步态抬脚经缩放后约 0.027 表现单位，在常规镜头下约一像素，默认移动时又接近每秒 3.33 个循环，容易呈现站姿滑动。原移动接收还依赖严格同帧标记，宏观步态队列在零位移／权限移交时缺少完整清理。以上已针对性处理；制作人最初看到的现场现象仍需人工复查，不能写成已现场复现并验收。

## 已实施

### 移动信号和默认驱动

- `EntityView` 改为一次消费有效位移样本，允许接收上次 LateUpdate 后提交的合法步进；有效零样本保留“被阻挡”的含义，不能用拥挤分离补成走路。
- 未收到样本时，只有仍由 Host 移动路径持有、且实际位移在合理小步范围内，才用已观测位移恢复步态；不把任意位置变化都当走路。
- 初建、增量生成和缺失表现绑定恢复共用同一个配置入口，恢复不改变人物根位置或重建玩法身份。骨架失败明确回退并保持稳定状态，不每帧重复加载；更换 Skin 时避免重新拾取同帧待销毁的旧骨架。
- 默认骨架成功时不再预加载旧整身 Idle 图；切换旧驱动或资源失败时才按需取旧图。
- `EntityView` Inspector 可查看实际 Driver、Profile、Action、位移来源／距离、WalkPhase、WalkBlend、骨架身体可见性和抑制原因，另有一次性日志菜单。它是开发诊断，不进入正式玩家面板。

### 俯视经营步态

- 相位继续来自实际有效位移，停走不清零；一轮改为约 3.2 表现单位，最高 2.8 轮／真实秒，真实移动速度不变。
- 正背向增加清楚的交替抬落脚、少量裤腿压缩和重心移动；侧面使用承重脚高度补偿，避免单纯绕髋旋转造成双脚飘起。
- 腿部行走与攻击上身分开。追击中真实出手仍能保留攻击，不再因此冻结步态相位；刚到工作点的末步与真实劳动命中也可同时表现。
- 暂停冻结；睡眠、失能、被搬运和解绑清理不适用步态。本地步进取得表现权后清掉旧宏观步态。

### 工具与劳动动作

- 工作从连续正弦摆动改为预备、快速落击、接触短停、回收的共用分段曲线，现有空手、斧、镐、锄、镰按各自手势表现。
- 工具／武器位置与手臂摆角解耦，由同一个平滑握点驱动手臂；长枪、镐、锄可使用显式第二握点。当前仍用整袖部件，通过有限袖长和肩位调整近似表达，不新增肘关节或握拳图片。
- 自定义附件的旋转现在同时作用于握点偏移，避免改角度后工具绕手漂移。工作附件与战斗武器保持分离。
- 成功砍树的既有结算通知只读表现层接触段，与原命中效果对齐；最后一击即使树已消失，也短暂保留真实落击。该通知不产生伤害、产出或第二套结算。移动、搬运、睡眠和生命失能不会补播旧接触。

### 宏观步态和床方向

- 宏观 NPC 每帧清理失去资格、转入本地移动／战斗／被搬运的旧步态；停用、世界切换和 runtime 失效也清理。零位移结束队列，真实到达末步保留。
- 宏观步态间隔排除暂停时间，避免高倍率暂停恢复后第一段异常放慢。人物根位置与 Core 投影仍只按原 WorldTick 更新，没有加入位置滞后或额外导航。
- 床图的视觉子层读取真实 QuarterTurns；旋转后按实际床宽高重算子层缩放，枕端同步旋转，不动根节点／Collider／床位几何。
- 骨架床姿沿床长轴、头朝枕端，并随床旋转；地面睡姿保留原有横卧表现。床内占用点保持原规则。

## 简短人工验收

在现有 LevelTester 重新进入运行，使用正常游戏缩放：

1. 主控右键走一段并转向、停下，再观察一名居民自主前往工作区或取食：两者都应有清楚交替步态，停下后自然收步；短距离抵达也不丢最后一步。
2. 进行砍树，以及现有农作／采矿中的一项：接近时走路，到位后使用对应工具；观察手是否贴柄、落击和最后一击是否保留，空手劳动不误拿武器。
3. 观察持枪巡卫走停；在 1×、2×／5× 中任选一个常用倍率暂停再继续，检查没有暂停摆腿、恢复后旧步态补播或长时间空摆。
4. 抽查旋转后的床和一次睡眠／搬运：枕端与卧姿方向一致，睡眠或被搬者不走路，搬运者仍正常行走。

若仍出现“位置在动但身体不动”，直接选中该可见人物的 EntityView 查看 Runtime animation diagnostics，记录 Driver、Action、WalkPhase 与 Rig Body Visible；这些读数能明确下一次应检查移动输入、状态门禁还是实际可见层，不需另做大规模验收。
