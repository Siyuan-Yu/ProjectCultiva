# 415 — 人物寻路、门口追击与抱持通行返修

状态：Design Confirmed / Implemented / Producer Acceptance Pending。制作人反馈战斗现有流程暂未发现问题，本轮集中修复房间、墙边、农田人物占位及抱持后的移动卡顿；不据此封板所有战斗内容。

## 单轮实施指令

1. 保持 Continuous Surface / exact WorldPosition / CharacterEncounter 空间真源不变。沿实际脚底寻路；抱持者与载荷只占一个移动主体，载荷显示偏移不作为障碍、落点预约或独立移动目标。保持墙、床、门洞、禁行区域与飞行原有规则，不用穿墙、瞬移或扩大攻击距离解卡。
2. 追击目标未显著变化且既有落点仍满足射程、视线和占位要求时续走原路线，不按攻击冷却反复从头重建。目标变化、门墙变化或真正失效时才重算。
3. 当前避让仅有左右单步，且每步长度受倍率影响；补有界短步与真实可达的局部绕人路径，验证每段静态通行及人物脚底碰撞。保留原最终目标、命令所有权、到达回调与精确交付半径；不能把绕行节点当最终到达。
4. 中途路线失效先尝试保留目标重规划。连续无有效进度必须受控恢复，无法通过时明确反馈，不能永久走路动画、假到达或在原地无限重发路径。空闲落点分配失败不得再退回已知被占用的中心。
5. 只做基础离线编译与最少静态检查；不启动 Unity，不编写或运行自动测试，不提交推送，不修改 Freeze、ProjectSettings、Packages、地图备份或 Snapshot v21。

## 已确认的接线风险

- 独立战斗每 0.2 秒请求 OrderCharacterApproach；该入口总是搜索新站位并 ClearPath，门口长绕行持续被重置。
- FilterCharacterStep 的左右单步与整段移动预算等长，快进时避让幅度放大；没有绕过静止人物的路径，农田工人和门口站人容易形成持续阻挡。
- TickMoves 在当前段失效时直接清掉待办；玩家路线没有与 NPC 日程等价的无进度恢复。
- freeStandRadius 搜不到空位后仍下发原中心，重新制造已知占位冲突。

## 人工验收范围

单人和队伍从房间内经门出入、绕床和墙角；抱持昏迷俘虏重复该路线并经过站立工人的农田；房内敌人追击出门后的玩家；1×／5×／20×下重复。观察是否沿可通行路线绕人、载荷跟随且不独立挤位；真正堵死时不穿墙、不误触到达交互。恢复通路后重新下令可走，切换命令能覆盖旧路线。

## 实施结果

HostMoveController 及 CharacterSpacing partial 完成：有效追击落点与剩余路线复用；直通路线直接验证后生成；自动路径按四分之一导航格细分移动；动态人物避让使用最多 68 节点的局部可见性图，保留静态路线转角并可越过被占用的中间航点，每段验证墙体、脚底及权限。局部绕行不更改最终预约点、移动 revision、回调或 Core 位置真源。

失效静态段重建至原终点；动态占用落点仅在原 freeStandRadius 内重选。载荷拒绝独立路线，脚底碰撞检查复验人物资格；拘押但能走者仍占位。飞行落点同样避开同层人物，保留原飞行资格／限制。

恢复任务每帧至多两个，每人间隔 0.6 实时秒；按路线剩余距离记录进度，暂停期间不累计，连续八个非暂停实时秒无进展时清除待办并显示道路受阻，不能伪装到达或触发床／农作／对话。转角近似到达后仍须与下一段连通；原命令后续被覆盖时正常释放恢复状态和预约。

Core／Data／Unity／Unity.Editor 四程序集离线编译全部通过，git diff --check 无格式错误。未启动 Unity、未编写／运行自动测试、未提交推送。地图备份、Freeze、ProjectSettings／Packages 与 Snapshot v21 未改。是否消除全部现场卡住情况仍须上述人工操作验证。
