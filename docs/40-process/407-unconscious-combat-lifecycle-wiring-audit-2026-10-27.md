# 407 — 昏迷、弥留、苏醒与战后保留接线复核

状态：Design Confirmed / Implemented / Producer Acceptance Pending。

## 本轮实施指令

制作人授权整体检查并修复现有身体流程，不更改 ADR-0065 已确认规则：首次战斗打空血保留一 HP、昏迷一倍速基准一百秒、暂停冻结且倍速加速；倒地不能自行行动或攻击；新的主动攻击才将昏迷／恢复期伤员转为零 HP 弥留；普通攻击弥留者不直接杀死，死亡须显式确认；苏醒不补满身体，返回仅恢复空间锚点，不覆盖真实身体状态。

- 补齐普通床休息与恢复处行动的失能取消、排队过滤和执行复验，不能在昏迷时继续睡床行动或保留旧恢复指令等苏醒后自动补满。
- 到达后执行的“攻击昏迷者”“杀死弥留者”“处决囚犯”须保存发令时的单次意图，并按原意图复验。目标途中状态变化只能取消，不可把一次攻击升级成处决。
- 普通战斗锁敌只持续攻击清醒对手；ReadyToEnd 的持续攻击同样在对手首次倒地后停止。明确对昏迷者重新发令时走单次近身攻击，不让自动索敌或在途旧弹补刀，也不把目标静默改成另一名敌人。
- 苏醒的床边站起及 Host 站位同步不得覆盖 CharacterEncounter 的参战人物空间所有权；非参战囚犯苏醒仍需消费实际床边位置，不能留在旧床中心。
- 旧精灵模式倒地时显示既有躺姿；默认模块人物继续使用真实 Downed 姿态，不移动身体根节点或改碰撞／导航权威。
- 逐段静态核对伤害入口、倒地表现、移动／攻击门禁、计时、苏醒、结算返回及存档字段。对正常主链不作无证据重写，不修改冻结架构、稳定枚举或 Snapshot v20。

## 静态复核与修复结果

- 床休息／恢复处已同时加入 Action 和 Order 的失能取消清单，执行前及继续执行时复验；床占用按本人释放。首次倒地会清掉旧指令，不会等苏醒后继续原恢复读条。
- 到达意图保存只读、session-only 的原操作种类，取消／移动沿原接近机制清理。原接近机制一律拒绝参战人物，导致显式补刀无法抵达；本轮仅给真实敌对参战双方、Active／ReadyToEnd、显式单次处理开放例外，普通对话贸易仍拒绝跨战斗所有权，ReadyToEnd 限当前主控。
- ReadyToEnd 原持续攻击接受所有 CanBeAttacked，第一次击倒后仍会继续攻击昏迷者；现与自动锁敌、在途投射物一样只处理清醒对手。重新对昏迷者明确发令才走单次近身处理，普通锁敌不能替代显式杀死。
- Core 苏醒释放床位前的站位转换及 EntityView 苏醒同步均排除实际参战人物；非参战的清醒被囚者也同步床边精确位置。旧精灵模式地面昏迷显示既有躺姿，不再只停站立帧。
- 近战／战斗技能共用首次打空血分支，据点防御伤害也进 TryEnterUnconscious；持续本地近战、自由瞄准与在途弹命中复验会跳过失能目标。Core 和 Host 的移动、主动攻击门禁读 Lifecycle，不因昏迷保留一 HP 误判可行动。
- 世界与战斗只各自推进所负责人物的昏迷时长，暂停不推进；Active 中可苏醒，ReadyToEnd 不因苏醒重新判开战。苏醒保留实际 HP／药量／恢复小数；CommitAndReturn／RestoreAnchors 只恢复空间、清战斗所有权，不重建身体池。Lifecycle 医疗字段、剩余昏迷时长和战斗衰减累积已有 Capture／DTO／JSON／Restore 接线，本轮不改格式号。

Core／Data／Unity／Unity.Editor 四程序集离线基础编译通过，diff 完整性检查通过。上述结论为源码接线核对，不代表已实玩验收。

## 人工验收边界

只做四程序集离线基础编译和必要静态核对，不启动 Unity，不编写或运行自动测试，不提交推送，不碰两份地图 previous 备份。

人工验收一轮：战中首次倒地（含原先正在休息／恢复者）后不能行动攻击；旧锁敌和在途攻击不自动补刀；重新明确攻击昏迷者只转弥留，途中别人已将其打成弥留时本次指令取消而不是杀死；显式杀死才确认死亡。对照暂停、1×／20×苏醒，仍在进行的战斗可恢复行动、已结束战斗不重开；返回及中途保存加载保留实际 HP、药量、昏迷／弥留进度和正确空间锚点。
