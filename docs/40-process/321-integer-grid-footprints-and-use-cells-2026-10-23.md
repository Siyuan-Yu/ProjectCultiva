# 整数格占地、人物站位与棋盘使用格

> 日期：2026-10-23｜状态：Design Confirmed / Implemented / Producer Acceptance Pending / 未提交。
> 制作人确认：建筑及场景物件占地和放置须格点化，蒲团为 1×1 格；人物站位为 1×1 格但连续移动，美术尺寸独立；棋盘两侧使用位置须显示脚印并对应真实人物使用位置。

## 本轮契约

后续布局／对象统计覆写见 [322](322-huangcun-compact-housing-and-cell-wood-walls-2026-10-23.md)：原 99 个村内对象保留，住宅收紧并新增 844 段 1×1 木围墙；现行版本 `0.0.7-huangcun-wood-walls`。下文 104 对象／0.0.6／sourceHash 为本轮实施时点记录，整数格规则继续有效。

- 所有静态建筑、家具、农田、树木、矿石、洞府入口和区域矩形的逻辑占地宽高为正整数格，左下角对齐所属 Surface／独立地图网格。1×1 物件中心位于半格坐标是正常的格心；底层 WorldPosition 经 CellSize 换算后可以是小数，不应直接四舍五入世界坐标。
- 人物按 1×1 地面占地处理，独立于 Sprite、骨架、选择碰撞框和人物美术缩放；允许沿合法路径连续移动，人物脚点不强制跳格。活人物的站位及移动避让使用同一格距，不因人物美术缩放而变大或变小。
- 棋盘本体 1×1 格；左右各相邻一格作为两个独立使用格，旋转后同向旋转。Core 到位目标与 Host 脚印读取同一座位几何。两格各显示一组朝向棋盘的脚印，当前坐姿／下棋动画继续使用，不新增棋局胜负规则。
- 蒲团 1×1、床 1×2、普通住宅 4×6 等已有正式模板保留。原导入物件的非方形比例来自旧坐标投影：将 `sourceCellsW/H` 所描述的整数逻辑格恢复为实际 footprint，清除导入比例对占地的影响，保留对象稳定 ID、房床关系及业务身份。
- 作者工具与运行内容校验阻止新小数占地再次进入正式地图。房屋及玩家建造链沿用现有整数 CellsW/H；修复势力旗等落点来源并检查独立洞府／战场地图、世界对象、预设旗及动态物件入口。
- 河流／道路中心线、连续人物位置、飞行弹道、美术缩放和作用距离不是静态物件占地，不按整数坐标强制吸附；本轮保留上一轮 7600×3400 世界、240×200 荒村、225×225 控制范围及道路河流原宽度。
- 本轮以“格”为玩家占地单位；上一轮讨论的“1 格＝1 米”仍未获得明确确认，不在本轮悄悄改成距离规则。

## 实施方式与验收

先修作者源，再由原有发布器重发三份地图产物；位置与田块细分发生变化，内容版本递增并复用已有旧档兼容门禁，保存文件保留。仅基础编译与必要静态数据核对，不编写／运行自动测试，不启动 Unity。

人工重点：新开局查看蒲团／棋盘／房屋格框；棋盘两侧脚印各对应一个使用者，人物到位与现有动画一致；普通和缩放后的角色均按一格站位，床位和农田工作仍可达。

### 制作人人工验收（新开局）

1. 检查蒲团／棋盘各为一格，房屋、仓库、田地边界对齐；人物不因美术缩放改变站位，仍可平滑行走并通过原房门。
2. 两人分别使用同一棋盘左右脚印位置，一人也能娱乐，退出后释放自己的位置；确认现有坐姿／落子动画没有错位。
3. 同伴修炼时到蒲团，饥饿可取食、精力低会返床，凡人仍可返家／下田；查看旗建造预览和实际落点一致。

以上为待验收项，不是已观察到的运行结果。旧存档文件不删除、不自动套用新占地；内容版本门禁会明确拒绝不兼容旧档。
