# 人物美术旧八步建议：现状核查

> 2026-10-18，只读审计；不是新功能批准或制作人验收。依据：制作人提供的八步截图、当前工作区代码/资源与 276、280～290 的实施记录。没有启动 Unity、运行自动测试或改动表现代码；当前工作区含大量未提交变动，本页以磁盘现状为准。

## 总判断

八步建议抓住了首批骨架样机的主要问题，但不能当作当前完成清单。1、2、4、5 的主体已有 Host 实施；3、6 的人工验收或性能证据不足；7 尚未启动，8 有局部接入但尚未整体收口。最新睡眠修复 290 是对 289 现场失败的再修，仍是 Implemented / Producer Acceptance Pending。25 个名录身份映射 12 套 Skin，不等于 25 人姿态/动作均已视觉通过。

## 与当前方向的关系

移动向量本来允许任意角度；视觉方向仍是 `HostStepAArt.Direction` 的 North/South/West/East 四项，`EntityView.SetArtDirection` 将斜向量归入其中一个轴。要做可信八向需新增斜向头/身视角和共用姿态、挂具/遮挡校验，不能仅扩枚举。该项不在旧八步中，也尚未实施/批准为批量资源生产。

## 建议的关闭顺序（Proposed，非实施指令）

1. 先在现有 LevelTester 复看 290：三种床抽查人物头像、被中身体、卧姿选取及血条；发现异常以现场截图/Driver 读数定位，不先标通过。
2. 同一正常镜头复核普通村民、主角、巡卫三 Skin 的走停转向、阿石/阿土/樵夫真实工作、巡卫武器与攻击；记录具体身份/方向/动作的通过与问题。
3. 在现有场景记录代表性同屏人数的帧耗时、GC、SpriteRenderer 和 Draw Call，并完成一次正式 Build 资源加载人工检查。未有这些数据前不退役旧图。
4. 若制作人确认八向路线，先做一套 Skin 斜向样机并与四向在正常缩放比较，再决定扩到其余 Skin；房间/道路/田地/UI 美术另列后续范围。

状态口径：本审计是只读结论；以上所有运行改动继续标为 **Implemented / Producer Acceptance Pending**，八向和后续环境/UI 制作为 **Proposed**，未写成 **Producer Accepted** 或 **Sealed**。
