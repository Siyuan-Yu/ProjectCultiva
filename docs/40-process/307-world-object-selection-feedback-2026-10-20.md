# 世界物件选中反馈（2026-10-20）

状态：**Design Confirmed（制作人本轮要求）/ Implementation Complete / Producer Acceptance Pending / Committed·Sealed（2026-10-20）**。Host 离线基础编译通过；开发代理未启动 Unity 或运行自动测试。

制作人指出房间边缘的蓝点含义不明，且床、门、木墙等对象被点选后缺少明确选中框。本轮只调整 Host 输入拾取和表现：可检视的世界物件在左键点选后显示贴合其交互范围的常驻细框；再次点空、选人物、物件销毁或离开加载区域时清除。人物沿用已有绿色选择环。界面点击不改变选择，房间与床等物件的现有业务面板、右键交互和真实身份保持原样。

房间蓝色线圈来自 `HostHousingAreaSelection.OnDrawGizmos`，只是编辑器 Gizmos 调试提示，不是玩家操作点。用正式选中框取代该调试提示；房间跨区块时合并同一 StableId 的已加载区域，避免只框局部地板。房门是房间现有两格开口的纯表现，左键可以独立检视“房门”并显示门口范围；不新增门的 Core 实体、通行规则、存档字段或右键行为。木墙沿用现有 `HostMapDestructible` 身份和生命值；墙的拾取优先于房间大面积地板，但床等小物件仍优先。

实施已完成：`HostHousingAreaSelection` 用 GameView 的双线矩形框替代 Gizmos 蓝圈；房间同 StableId 的已加载地板范围合并，床/门/墙按各自范围框出；原有可检视地块、树、议政厅、势力旗与工作区沿用同一反馈。门口左键登记为只读 `roomDoor` 物件，右键不增加门专属行为；墙在房间地板之前拾取。人物绿色环、业务 authority、存档字段与建造/通行规则不变。

人工验收：在 LevelTester 点击房间地板、床、门口、木墙，确认蓝点消失且各有贴合对象的青色细框；再点击树、农田或其他可检视目标，确认框随目标移动；点空白或人物后确认物件框消失；点界面按钮不应改变世界选中目标。若房间跨区块，确认框覆盖同一房间的已加载部分。此处结果待制作人反馈，不把离线编译写成现场通过。

## 2026-10-20 现场反馈返修范围

制作人截图指出：议政厅选中框偏到建筑上方；医疗房中央仍有蓝点，议政厅文字旁出现石牌。静态定位显示议政厅框按 `HostControlCoreQuery` 的逻辑占地中心估算，未取 `StepAArtVisual` 的实际渲染范围；蓝色实心圆由 `HostInteractSpotPresenter` 绘制，仅显示交互点，不承担拾取或日程；石牌由 `HostMapGraybox.BuildZoneLabel` 对所有地点标签无差别叠加 `ART-UI-007`。上一版只移除选中时的 Gizmos 线圈，误把截图中的常驻实心蓝点也归到同一来源，故未解决该点。
