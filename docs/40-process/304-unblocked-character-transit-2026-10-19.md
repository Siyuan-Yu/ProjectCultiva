# 行走阶段人物非阻挡穿行

> 状态：Design Confirmed / Implemented / Producer Acceptance Pending / Committed·Sealed｜2026-10-19

制作人复验 303 后明确要求：所有普通 NPC 与我方人物均不阻挡主角及其他人物沿合法路径行走；先允许直接穿过，解决窄路被人物卡住。议政厅攻击另属 301 ACR，不能与此移动修复混作已实施。

静态核查表明 303 只缩短同队绕让并调整慢步顺序，`FilterCharacterStep` 仍把其他活人物当在途障碍；`IsCharacterStepClear`、六向绕行与 30% 减速仍可能使人物受阻。右键普通落点已有 1.25 范围内空位解析，精确任务与交互有自身到达检查；可把**行走中的人物占位约束**与**最终停驻/工作站位**分开。

本轮 Host 共用移动：行走途中只按原 WalkGrid 检查墙、门、家具与静态连通，其他活人物不减速、不绕、不互推、不触发等待穿行阈值。静态核查又发现终点占位会阻止最后一步和完成指令，因此终点也允许与人物临时重合；取消行进中因新占位反复改终点。普通右键与跟随命令**下令时**仍尽量从允许范围解析邻近空位，若范围内没有空位则退回原请求点尝试静态可走路径，避免仅因人物拥挤拒绝下令；之后有人走进目标点则按原路径抵达。精确交付和交互/攻击本身的合法范围及站位检查仍保留，防止穿人越权完成任务；相关任务若因站位要求未满足会由其任务逻辑继续处理，不再由移动器卡在最后一步。WASD 连续手动行走也能穿人，松键恰好停在人身上时不进行突然推开；这是制作人本轮优先级取舍。

不改 Core／Data／Content、Snapshot、碰撞体、导航权威、场景或 Freeze。基础离线编译、最少静态检查后由制作人在同一住宅窄道人工验收：主角右键穿过同伴和 NPC 时速度不再掉到 30% 或停顿，NPC 对向通行；目标点恰被 NPC 踩住时移动指令仍能结束；墙与门洞继续挡路。普通右键落点下令时尽量站在邻近空位，精确任务不能因穿人而在错误位置完成。未启动 Unity、不编写或运行自动测试。后续制作人已明确授权本轮版本封板与上传；人工运行验收仍待完成。
