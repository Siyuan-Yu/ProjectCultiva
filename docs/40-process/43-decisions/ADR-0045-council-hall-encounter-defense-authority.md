# ADR-0045 — 议政厅在独立遭遇中的建筑防御权威

> 状态：已采纳、已实施、Producer Accepted / 封板授权（制作人 2026-10-19 确认议政厅攻击及弹道现场验收通过并要求推送）。范围仅为固定议政厅，不扩展为通用建筑武器系统。

> 后续扩展：[ADR-0046](ADR-0046-faction-flag-encounter-defense.md) 在相同的单 `SourceSiteId` 防御权威下接入势力旗。议政厅既有验收不等于势力旗已获人工验收。

## 背景

`CharacterEncounter` 的 `Participants` 只保存真实人物。议政厅既是固定 SiteCore，又能在战场被攻破和接管；不能给它捏造 Character 身份，或让 Host 根据可见 Sprite 自行扣人物 HP。制作人规则见 [301 ACR](../301-acr-council-hall-spirit-defense-2026-10-18.md) 和 [战斗 §12.2.1](../../20-systems/23-combat.md)。

## 决定

- 独立遭遇保留人物 roster 不变，另存最多一个固定议政厅防御记录：Site、Core WorkArea、参战时 Owner、同源占地、战术冷却和本场停火标志。仅同源战场中完整包含的当前行政 Site 固定核心可加入；附近普通遭遇与攻城遭遇使用同一判定，只有本场正式存活参战者与 Owner 存在战争关系才创建记录。没有建筑记录就不开火。
- 建筑仅在 Active、未破防、未停火时，从正式人物 roster 中按人物当前势力与该建筑 Owner 的战争关系筛选存活目标。射程从作者配置的真实占地边缘计算，不用 Site 行政控制半径或可见 Sprite 大小；距离最近、同距 EntityId 最小者优先。冷却随战术时间推进，暂停及 ReadyToEnd 不开火。建筑不增加人物人数，也不改变现有战斗胜负或返场锚点。
- 建筑攻击力 20 走普通普攻的基础攻防和正式护盾／HP／弥留流程，但不套用人物装备、斗技、运输等仅适用于 Character 攻击者的权限。建筑伤害事件以 SiteId 标识来源，`actor=EntityId.None`，不捏造人物击杀归责；Host 仅消费成功的领域攻击来播放统一可见弹道。
- 破防时在领域状态立即锁定本场停火；同场接管恢复建筑耐久、改变 Owner 也不重启。下一场重新按当时 Site Owner 判断。遭遇 JSON 在现有格式中增加可选建筑记录：旧格式记录缺席即旧战斗不补发历史攻击，新存档严格校验实际 Site/Core 绑定、范围及计时，不改变顶层 Snapshot 版本或稳定枚举值。

## 边界与后果

只支持当前遭遇选择的唯一 `SourceSiteId` 议政厅；野外战场碰巧画入其他 Site 建筑，不视为正式加入。若将来同一战场允许多个 Site 防御设施，需另行设计多建筑 roster，不能复制本 V1 单记录。固定核心的物理占地由已发布作者配置绑定至 `ControlCore`，不修改控制范围、攻城接管或世界时间轴。Unity PlayMode 与视觉验收须由制作人完成。
