# ADR-0002：不采用 Unity ECS，使用普通 C# 组合模型

- 状态：**已采纳**
- 日期：2026-07-31
- 决策者：项目负责人（架构冻结收口）

## 背景

需要为正式 `XianXia.Core` 选择实体组织方式。可选 Unity DOTS/ECS、自研 ECS、或普通 C# 面向对象／组合。

## 选项

**A. Unity ECS / DOTS**  
- 优点：大规模实体性能潜力  
- 缺点：工具链与心智负担高；与单人+AI 协作不友好；多数玩法实体规模在 30～50 高精度 + 群体聚合，不需要万级实体仿真  

**B. 自研纯 ECS**  
- 优点：表现层无关  
- 缺点：重复造轮子；序列化与调试成本高  

**C. 普通 C# 组合模型（Character + 预定义组件）**  
- 优点：可读、可测、易序列化；契合四层模拟；AI 辅助改代码正确率更高  
- 缺点：极端大规模个体仿真不是长项（本项目用群体层规避）  

## 决策

选 **C**。逻辑层不采用 Unity ECS。

## 影响

- 实体模型以 `34` 为准。  
- 以后若改 ECS，需新 ADR 并重写 Core 边界，成本极高。
