# ADR-0071 城池可编辑巡视路线

状态：Accepted / Design Confirmed（2026-10-27制作人明确要求）；实施与人工验收单独记录。不修改Freeze、程序集边界或Snapshot稳定字段／数值。

## 规则

巡视点属于城池，是同一Continuous Surface内的真实WorldPosition。占领前只读；我方占领且核心有效后可在巡卫排班入口打开地图编辑，按点击顺序添加、删除、前后调序、全部清空再设置，保存前为草稿。无点即无巡视路线，不回退工区／房间。最多64点。

巡卫在当班Patrol／Inspect时按列表顺序循环；真实到位后才等待，等待结束才去下一点。主管巡视时随机选不同于上一个的点，也须真实到达后停留。等待口径为WorldTick：每点clamp(48 / 点数,2,24) Tick，1倍速约相同实秒，倍速与暂停随世界进度。8点每点6 Tick；移动时间不扣等待。

荒村初始8点沿墙依次为墙内西南角、南边中点、东南角、东边中点、东北角、北边中点、西北角、西边中点，距边界约2.5格。其它城池不自动猜测巡视路线，由玩家安排。清空后的荒村不自动恢复初始点。

战斗、惩戒追赶、玩家／事件指令、救护、运输、伤病和紧急需求保持优先。取消巡视时只清自己发出的路线意图，不清他人的移动命令。道路被堵显示等待／重试，不假报到位，不跳过巡卫规定顺序。

## 实现边界

Core负责权限、点位合法性、顺序、到达、等待与随机选择；Host只编辑输入、点位编号／连线预览与既有导航表现。路线不创建虚假的WorkArea，不修改地形或建造物。

沿用既有ContentCounters持久化命名空间`base:patrol-route:<siteId>`，记录configured、count、revision和点位x/y绝对微单位整数及符号位（Surface由本城CoreSurfaceId约束）；人物进度独立记录路线版本、游标、等待阶段和剩余Tick。该命名空间是真源，UI与驱动不另存权威路线。坐标保持Surface+WorldPosition，不用Hex或LocalMap替代。沿既有Snapshot v21进度序列化，无新wire字段；读档不重建已清空路线或重抽已选目标。

验证仅基础编译与最少静态完整性核对；不启动Unity、不运行自动测试。人工验收见420。
