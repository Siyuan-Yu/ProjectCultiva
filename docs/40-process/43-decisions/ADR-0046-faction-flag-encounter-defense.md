# ADR-0046 — 势力旗复用独立遭遇核心防御

> 状态：Design Confirmed / Implemented / Producer Accepted / 封板授权｜2026-10-19。制作人明确确认本轮势力旗战斗内反击已验收通过，随后授权当前工作区剩余改动全部提交并上传；开发侧未自行运行 Unity。

## 决定

- [ADR-0045](ADR-0045-council-hall-encounter-defense-authority.md) 的 V1 防御范围由固定议政厅扩展至正式 `SiteCore` 势力旗；每场仍仅解析当前 `SourceSiteId` 的唯一核心，不因旗帜可见就让周边其他 Site 一同开火。两类核心共用一次战术计时、战争目标筛选、占地边缘射程、攻击力 20、基础攻防、护盾／生命／弥留及 Host 弹道。旗帜不伪造 Character；有守军战斗仍按原人物与正式目标结算，只有无守军拆旗适用下述“核心为唯一敌方目标”的结束规则。
- 旗帜占地从正式 `FactionFlagState` 的连续世界中心和该 Surface 的格距派生 4×4 格物理范围，与 Host 碰撞占地一致；不用行政控制范围或 Sprite 尺寸。仅当前有效、HP 大于零且与核心 Site 及 Owner 身份一致的旗可参战。旗帜被正式击毁时本场永久停火；原有移除旗帜、Site inactive 和 Claim 历史规则不变。议政厅破防、接管与同场停火规则不变。
- 遭遇只保存一份核心防御状态，带明确固定议政厅／可拆势力旗种类、核心资产身份、战时 Owner、占地、冷却和停火位。读取旧 `councilHallDefense` 字段视为固定议政厅；新写入使用可选 `siteCoreDefense`，不改变顶层 Snapshot 版本。存档严格校验当前核心绑定；已击毁、停火的旗允许以历史战斗记录恢复，但不得复活或重新开火。
- 制作人进一步明确：无守军旗被单独攻击也必须反击。原“无守军时连续地图直接拆旗”入口改为旗帜作为唯一敌方 SiteCore 的独立遭遇；真人 PlayerParty 仍是正式人物参战者，敌方人物 roster 可以为空，但旗帜必须真实有效并在本场占地内。旗帜击毁按原正式目标使战场进入可结束，玩家全员失能则战败；不能因敌方人物为零而刚开始就自动胜利。不得伪造守卫 Character。普通人物对人物遭遇仍要求双方真人小队。

## 边界

普通连续世界和离屏模拟不发射；没有正式人物参战和战争关系就不参战；不扩展到多核心炮塔、玩家背包旗帜或新的建筑系统。无守军旗使用现有人工确认与独立战场流程，而不是大地图自动开火。Unity 现场视觉与战斗验收由制作人完成。
