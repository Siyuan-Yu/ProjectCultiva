# ADR-0055：固定议政厅据点与五级行政范围

> 2026-10-26 更新：制作人已批准 [ADR-0060](ADR-0060-final-world-geography-and-site-retirement.md) 的主世界定稿迁移。下文 §2 关于 102 个旧旗 Site 在**新开局主世界全部保留**的要求，由 ADR-0060 的逐项退役决定替代；退役旧 ID 不复用；保留 ID 依逐项表迁址／改名／改属，旧档原文件仍保留。唯一固定 SiteCore 与等级范围等其余规则继续有效。

> 日期：2026-10-25。状态：**Producer Design Confirmed / Implemented；未人工验收／未封板**。制作人已确认规则方向、102 个既有据点均纳入及等级倍数；实施记录见[345](../345-fixed-sites-and-town-levels-architecture-change-2026-10-25.md)。本 ADR 不修改 Freeze 正文或稳定 ID／Snapshot 数值；实施按制作人“全部实现”授权扩充了 Core／Data 内容契约。

> 后续 [ADR-0056](ADR-0056-five-level-town-separation-and-world-expansion.md) 增加作者布局约束：当前 108 城即使全部五级也不得互相贴边。下文通用解析规则仍能处理旧档或其他世界的历史重叠，但本次主世界不再布置重叠理论范围。

> 2026-10-25 最新尺寸覆写：[357](../357-golden-core-energy-and-town-footprints-2026-10-25.md)取旧一级 225 格的 **0.8**，并维持原等级倍率，现行 1～5 级长宽为 **180／270／360／450／540 cells**；全部固定城镇实体外墙放到各自行政范围边缘。此前 [356](../356-world-map-flight-travel-and-level-one-size-2026-10-25.md) 的一级 0.75 和二至五级旧绝对尺寸是已被本决定替代的实施历史；下文 225 基数与旧绝对尺寸同样是历史，不再是当前运行数值。

## 决定

1. 正常新游戏不提供放置、建造、拆除或以战斗摧毁「势力旗」来创建／删除 WorldSite 的玩法。玩家取得新据点，只能占领世界中已经存在且有唯一固定 SiteCore 的 WorldSite；攻破核心防御后仍须按正式接管流程占领，核心实体不消失。玩家可以给已拥有的据点升级议政厅，扩大其理论行政及建设范围。接管保留同一个 Site ID、名字、等级、核心、资产和既得控制历史；不会自动改变居民身份与日程。
2. 当前 102 个由 `factionFlags` 生成的正式预设据点，**全部保留原 Site ID、名称及对外引用身份**，改为可占领、不可拆的固定议政厅据点。它们不再是运行时放置的旗帜 Site。现有荒村及其他固定 Site 保留身份；本轮允许调整据点中心、蓝图和道路，但迁移表必须逐一记录旧／新坐标与所影响的角色、服务和资产锚点。内部既有 `site:runtime:base:flag_*` 字符串作为稳定 ID 可保留，不能因字面含 `flag` 就批量改名。
3. 主 Surface 以现行一级 **225×225 Surface cells** 为基数，等级 1～5 的控制范围长宽倍率依次为 **1／1.5／2／2.5／3**。对应宽高为 **225／337.5／450／562.5／675 cells**，面积倍率为 **1／2.25／4／6.25／9**。小数格数作为世界长度参数解析，不要求覆盖边缘落在整数格。一级荒村保留；青石镇与 **102 个旧旗据点** 暂按三级初始化；其他独立固定 Site（青石关、灵地、林间、庄园）保留当前等级，是否属于三级城镇待其身份设计确定，不擅自一并升级。当前不预设五级城市，五级仍是可升级的规则上限。其他 Surface 如有独立配置，须保持同一倍率关系而按其 `cellSize` 解析。
4. 等级表规定的是**理论行政／建设范围，不是同尺寸的密集建筑蓝图**。城区可随内容与升级逐步扩建。街区、地形、道路和建筑仍用同一 Continuous Surface 的精确坐标，不能以等级方框裁出独立地图，也不能把理论覆盖重叠当作互相叠盖房屋的许可。升级只产生既有规则下的新增 Claim；不得追溯抢占他方既得控制，实际管理者仍唯一。
5. 青石镇采用可辨方向的横平竖直街路，先有一条南北主街、一条东西主街，必要时增一条平行服务街／短连接；减少无目的分叉。公共建筑、住宅和商铺沿街混排，不强制四区、四门或与荒村相同的模板。其他据点可按地形和身份变化建筑与材料，但保持简洁通路和真实服务接线。

## 与旧决策的关系

- **部分替代** [ADR-0032](ADR-0032-sitecore-administrative-and-construction-range.md) §2、§8 的正常产品「玩家建旗创建新 Site／拆旗失活」规则；其唯一核心、固定核心接管、理论重叠、既得控制、资产独立及人物不随易主移动等条款继续有效。
- [ADR-0046](ADR-0046-faction-flag-encounter-defense.md) 的旗帜防御与拆旗结算是已验收的历史实现，正常新游戏由固定核心防御／接管路径取代；不得抹去历史验收记录或直接删除稳定旧档输入。
- 本 ADR 不改变 [ADR-0038](ADR-0038-continuous-world-legacy-migration-final-seal.md) 的 Continuous Surface authority，也不重新引入 Hex／Army 正式依赖。

## 实施前必须解决的迁移边界

1. 新游戏的 102 个 Site 从作者源的固定 `siteRegions`／`controlCore` 建立；同一 ID 不能再由 `FactionFlagSiteCoreBootstrap` 重复创建。每个 Site 恰好一个固定核心，核心房屋与实际占地、入口、接管点相合。旧旗 marker／建造菜单／摧毁入口在正常产品退出，但稳定字段与兼容识别不能未经迁移就删掉。
2. 旧档可能含已放置的玩家旗、旗防御遭遇、`factionFlags`、Claim 和旧 Site 引用。本次**采用现有内容版本隔离路径**：新布局发布时提升 BaseGame package version；旧存档原文件保留，正常产品以 `IncompatibleContentVersion` 拒绝不匹配内容并提示新开局，不把旧旗／Claim 硬转成新固定城镇，也不改 Snapshot schema、稳定 ID 或静默迁移。当前 Restore 在内容版本比较前还进行 schema／状态校验；实施时应确认读档 UI 对各类旧档都能清楚解释失败原因，不能笼统宣称所有旧档均先命中内容版本错误。后续若要导入旧档，再独立设计无损离线转换。新游戏的迁移与旧档迁移是两件事。
3. 已有一级 Claim、Snapshot 与角色位置不可因修改内容配置而偷偷扩为三级或平移。新开局采用新布局；旧档坐标与历史 Claim 留在旧文件中保持原义。实施时必须确认正常读档入口传入当前 package version，不能仅改版本字符串却继续加载旧地图状态。
4. 升级服务已有 `WorldSiteCoreLevelService.TryUpgrade`，但正常玩家入口、资格、成本、等级上限、升级后的表现和存档闭环尚未完成；不得仅把五行数字写入 JSON 就宣称可升级。
5. 旧 102 中部分是宗门／关隘／资源据点，固定核心可在世界观上称议政厅／宗门议事堂／驻地议事所，但**规则上同属唯一固定 SiteCore**。不把所有地点做成同一张城市蓝图。
6. 当前固定核心绑定把默认等级写成 1，而静态 `siteRegions` 没有对应旧旗 `EstablishedOrder` 的作者字段。实施迁移须明确初始三级与重叠 Claim 的先后来源；新开局可采用经设计确认的新优先级，但不能由加载顺序碰巧决定实际控制。若需要扩充内容字段或改变 Core／Data 契约，应先单独确认边界，不能把它当成蓝图美术调整。

## 验收与状态

本 ADR 只确认目标规则。实现时以[345 单轮迁移指令与静态审计](../345-fixed-sites-and-town-levels-architecture-change-2026-10-25.md)为范围入口；编译与静态引用检查只证明实施接线，地图通行、战斗接管、升级、性能和旧档行为仍待制作人人工验收。未取得现场验收前不得标记 Producer Accepted。
