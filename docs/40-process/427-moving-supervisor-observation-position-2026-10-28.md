# 主管移动途中观察范围的位置同步返修

日期：2026-10-28。状态：Design Confirmed / Implemented / Producer Acceptance Pending。

制作人明确主管移动过程中，处于其观察范围内也应计算发现。沿 423 室外清醒观察规则与 425／426 最新参数：主管／巡卫观察半径 50 格，压力上限 15，普通违规被发现每 WorldTick 总计 +1，未发现则 -1 至 0，暂停不推进。巡视、自由活动、娱乐和往返设施途中均可观察；进入房间、实际睡眠／修炼、失能及更高空间／运输控制权仍按原规则停用。

## 原因与单轮实施

Core IsOnWatch／CanObserveOutdoors 已无“必须停在巡视点”或“必须当前执行巡视课表”限制；但 HostMoveController 移动逐帧写回只覆盖独立战场、囚犯／战场旁观者及具有本地移动所有权的凡人。主管这类非凡人、个人日程移动角色没有成功写回普通精确位置，往往直到 SyncLocation 到达处理才提交。范围圈却按 EntityView 的当前脚底移动，导致圈的位置与 Core 观察位置不一致，也可能在出入房间时错误判定室内资格。

在既有逐帧脚底捕获入口补普通室外个人位置提交：独立战场捕获不适用时，调用 CommitContinuousNpcPosition，由它复验当前 World、Surface、个人位置所有权、地图边界、禁行／拘押与同步迁移保护。只在实际移动的角色上执行，不添加每帧全实体／全建筑扫描，不用 Host 自行计算压力或建立第二套观察坐标。

发现、牢房禁区、私人营地／秘密修炼和室外资格继续通过 Core CharacterWorldPresenceQuery 读取同一精确位置；范围圈仍只展示实际脚底和既有 50 格参数。小队、玩家队伍、背景旅行、Separate Space、独立战斗和恢复重建的空间所有权不变，不将目的地、设施中心或旧站点当作当前观察中心。

只做四程序集离线基础编译和最少静态检查；按 AGENTS 不启动 Unity、不编写或运行自动测试、不提交推送，不改地图、ProjectSettings／Packages 或 Snapshot v21。

## 人工验收

1. 主管或巡卫走向下一巡视点时，在其当前 50 格范围内真实违规，观察每拍压力增加；离开所有观察圈或履行日程后每拍下降。不要等 NPC 到点才判断。
2. 站在 NPC 已走离的旧位置附近、但已在当前圈外，不能继续按旧位置被发现；以当前圈内外和墙体视线为准。
3. NPC 从室内走到室外后观察恢复，进入房间后停用；返床途中仍清醒且在室外时保持观察，实际睡眠／打坐后停用。
4. 用移动中的观察者分别经过牢房禁区和私人营地，核对原即时追赶入口；暂停及 1×／20×核对既有 WorldTick 频率。顺带检查非凡人日程移动、存读档以及战场／小队人物未被普通位置捕获覆盖。

## 实施与检查

已在 HostMoveController 现有脚底捕获中接入普通个人位置提交，复用 CommitContinuousNpcPosition 的 World／Surface／空间所有权与同步迁移保护；战场捕获成功时不走普通位置提交。Core／Data／Unity／Unity.Editor 四程序集离线基础编译全部通过，直接调用和 diff 格式检查通过。未启动 Unity、未编写或运行自动测试，现场仍按上述路线人工验收；未提交推送，0.0.48／v21不变。两份既有地图备份未改动。
