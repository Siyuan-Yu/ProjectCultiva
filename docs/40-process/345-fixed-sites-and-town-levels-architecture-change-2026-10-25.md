# 345｜固定城镇、议政厅等级与世界重排变更单

> 日期：2026-10-25。状态：**规则 Design Confirmed；具体地理落点与升级成本待内容制作；未实施、未验收、未提交**。唯一决策入口：[ADR-0055](43-decisions/ADR-0055-fixed-council-hall-sites-and-five-level-control-range.md)。本页是 Architecture Change Request 与下一轮单份实施指令；不能把它当成代码已接通。

## 制作人已确认

- 荒村一级；青石镇与 102 个由势力旗生成的既有据点暂为三级；青石关、灵地、林间、庄园四个独立固定 Site 暂保留当前等级，待按地点身份分类；暂不摆五级城。
- 一级基数 225×225 cells，1～5 级长宽倍率 1／1.5／2／2.5／3，五级面积是一级的 9 倍。
- 移除玩家新建势力旗据点的正常玩法，只能占领既有固定城镇；保留 102 个据点位置关系中的身份和名称，允许重排中心与道路，以议政厅升级扩张控制范围。
- 青石镇不采用荒村四区模板。街路横平竖直、方向清楚、分叉少，建筑功能与等级高于荒村，但不把一个小镇做成巨型迷宫。

## 当前工程事实与规模约束

|项目|当前作者／运行数据|变更含义|
|---|---|---|
|主 Surface|7600×3400 cells，50×50-cell Chunk|仍是同一连续世界；道路、地形、Site 共用精确坐标|
|一级范围|`world_spatial_rules.json` 仅配 225×225|二至五级尚无内容行|
|现有站点|108 份 `worldSiteBlueprintPlacements`；102 份 `runtimeLayout.factionFlags`，另有 6 个 `siteRegions`|要迁 102 个已有身份，不能新增 102 个替代 Site|
|102 旧旗 Site|`site:runtime:base:flag_*` 等稳定 Site ID；当前通过 `FactionFlagSiteCoreBootstrap` 创建、`CoreIsRemovable=true`|新开局改由固定核心作者数据创建；旧档需专门方案|
|青石实体蓝图|140×160 cells、14 间同型屋，现有服务部分已有角色与入口|三级 450×450 是行政范围，不等于现有城区已扩成 450×450|
|升级服务|Core 有 `WorldSiteCoreLevelService.TryUpgrade`，正常玩家交互未接线|成本、资格、上限、UI 与保存闭环仍需设计和实施|
|固定核心初始化|`RebindPresetWorldSiteCoreMetadata` 当前把固定核心等级硬设为 1|仅新增五级 JSON 不会让青石／102 个旧旗 Site 初始为三级|
|初始控制先后|旧旗有 `EstablishedOrder`；固定 `siteRegions` 当前无同等作者字段|102 个 Site 改固定后，重叠处的实际管理优先级可能变化；须明确新开局规则，不可偶然由排序决定|

三级的控制宽高为 450×450。按当前 102 个旗中心做矩形初算，**204 对**三级理论方框重叠，最小 Chebyshev 中心距约 252 cells。这不是 `TerritoryClaim` 的非法状态：ADR-0032 本来允许理论重叠，实际控制仍唯一。但建筑街区不能互相压住，世界道路也不能被蓝图堵住。仅青石加 102 个旧旗据点这 **103 个**三级 Site，若都要求彼此独立的 450×450 实体城区，总面积合计约 **2086 万格**，已是 7600×3400 主 Surface 面积的 **约 80.7%**，且还没计其他 Site、河流、山地、道路和野外缓冲。故**不能**将等级宽高误作每镇必须填满建筑的边界。重排要优化中心、城区占地和通路，不能承诺把所有理论范围的交集清零。

现有 102 旗中心中另有 **5 个**三级方框会越过主 Surface 边缘：`base:flag_sect_qingxiao_capital`、`base:flag_sect_qingxiao_node_3` 位于 x=150（至少向内 75 cells），`base:flag_sect_guanxing_node_3/4/5` 位于 y=3260（至少向内 85 cells）。这些是重排的确定优先项，实际落点还要核对蓝图、地形与道路，不能机械平移而留下原地点／人物锚点。

## 作者与运行迁移清单

1. 从现有 composition 已导出[108 行 Site 身份清单](345-site-identity-inventory.tsv)，逐一保留原 Site ID、显示名、类型、Owner、当前锚点、蓝图源和预定等级；目标中心及固定 Core StableId 留待地理排布后填写。继续补原 FlagId／`EstablishedOrder`、入口、关联角色／地点／服务与道路接点。102 个旧旗 Site 在正常新游戏不再以旗创建。
2. 先规划世界骨架：保留荒村一级与主要河桥地形，青石为三级；对每个据点标出**行政中心、实体建成区外轮廓、主路接点**三种不同几何。优先解除实体蓝图与道路、河岸、其他实体蓝图的碰撞；理论行政重叠由原 Claim 规则处理。先检查主 Surface 边缘是否容纳升级范围，不在无授权情况下扩大世界。
3. 青石先出正交主街和地标：南北、东西各一条主通路，必要时一条平行短街；议政厅、坊市／拍卖、书阁、医馆、客栈、工坊与住宅沿街混排。真实服务、NPC、商店、任务与建筑门口一一对应，待设计的炼丹／炼器等机制不能以空按钮假装已开放。再把可复用的街路／功能模块应用到其他据点，按宗门、关隘、镇、资源点区分材质和用途。
4. 在正式作者蓝图及 composition 中逐个添加唯一固定 `controlCore`，把 102 个旧旗身份发布成固定 Site，移除新游戏 `factionFlags` 创建源与旗表现；避免同一 ID 同时在静态和旗 bootstrap 注册。任何名字／坐标的修改都核对 `sitePlaces`、`openingEntityAnchors`、居民名册、商店、拍卖、任务、路线和世界图。新开局初始三级和重叠 Claim 的确定先后必须有明确作者／架构规则，不能依赖当前固定核心一律一级、默认排序的偶然结果；旧档 Claim 保持在旧文件中不变。
5. 增加五级内容范围配置并明确新开局默认等级；升级入口须有合法 Owner、相邻等级、资源消耗／前置、范围扩张和反馈。升级没有重置旧 Claim，易主没有免费升级或迁移人物。固定核心战斗继续走真实 CharacterEncounter 与正式接管，不能继承「打碎旗就 Site inactive」的结果。
6. 旧档采用现有 package-version 隔离：新布局发布时提升 BaseGame 版本，旧存档保留原文件，当前加载入口以 `IncompatibleContentVersion` 提示新开局，不在正常读档时把玩家动态旗、旗防御、Claim、建筑和人物强行搬迁。静态核对旧版本判定实际接入；未来离线转换另立设计。不得因此删除稳定字段或擅改 Snapshot schema／Core/Data 边界。
7. 保持 streaming 与性能预算：大量新建筑、角色、遮挡与路线应按 Chunk/视野物化，不把所有 108 站的物件逐帧扫描；人工在青石、边界和 20 倍速路线复核 F9 慢帧。已有 343 性能报告是扩容前基线，不是新布局的验收。

## 下一轮唯一、可复制的实施指令

> 依据 ADR-0055 和本页一次完成「固定据点迁移＋五级范围＋青石正交街路＋世界道路／据点重排」的直接接线。保留 108 个原 Site ID 和对外身份，102 个旧旗 Site 改成固定不可拆的唯一议政厅核心，正常玩家只通过正式接管取得据点并可升级；荒村一级，青石与 102 个旧旗 Site 暂三级，其他四个独立固定 Site 保留当前等级待分类。作者源、发布后的运行数据、Core 建造／战斗／占领／升级入口、Host 菜单／表现／地图、角色与服务锚点、内容引用和新旧包版本隔离在同一轮闭环。重排中心与道路时保持 Continuous Surface 权威，行政方框与实体城区分离，不让城市蓝图互压。青石采用少分叉的正交街路，并落实已有服务的真实建筑；未设计的高级生产机制暂不开放。旧档保留原文件，发布新包版本并按现有 `IncompatibleContentVersion` 路径明确提示新开局，不擅改稳定 Snapshot schema／ID 或 Core／Data 边界。实施后只做基础编译和必要静态引用／文件完整性核对；不运行自动测试、不自行启动 Unity。制作人人工验收新开局的地图通行、各级范围、攻占／升级、保存读取及移动帧时。普通实施不自动提交。

这是一轮实施指令，**不是将各步骤拆成多个独立交付**。实际地理落点与升级成本是实施时必须明确的内容数据，不能以“先全表三级”跳过。
