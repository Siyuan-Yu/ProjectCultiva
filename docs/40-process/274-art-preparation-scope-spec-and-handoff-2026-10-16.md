## 阶段与完成标准

顺序固定为：**工程与内容盘点 → 制作人确认范围和规格 → 少量风格样本 → 少量样本接入验证 → 分批制作 AI 首版 → LevelTester 实际游戏验收 → 后续人工外包逐项替换**。每一步的通过记录单独进入 273；“AI 已生成”“Prefab 已绑定”“制作人已验收”不可互相替代。当前已完成盘点并确认下述整体风格方向；方向数、帧数、运行尺寸及首批样本效果仍待确认，不进入全量 P0 制作。

范围是当前 `base:scenario_playable_day`、`base:roster_level_tester`、荒村作者源及发布 Surface、现有正式 UI／战斗／生活／修炼／商贸入口和已明确近期内容。未批准的怪物、技能、城市、季节套装、物流等只记暂缓类别。跨旗帜救援、局部加载标记清理、囚床交接及其它近期实现仍按 [247](247-project-handoff-current-state-2026-09-18.md) 和 [42](42-devlog.md) 的真实待验收状态，不能因美术筹备而标记玩法通过或系统封板。

本阶段完成判据：273 每行有稳定 AssetID、工程依据、复用关系、接入状态和待确认项；先做下文**两张综合视觉参考样张**，通过后才拆少量独立素材并在 LevelTester 的一小片场景接入验证。样张不是可运行资产，不能改成“已接入”或“已验收”。少量样本接入后再核视角、比例、遮挡、可读性、状态刷新与资源引用；没有 Unity 人工验收之前，不标“已验收”。

## 盘点基线与数量口径

`base:roster_level_tester` 有 **25 个名录人物条目**，并非 25 套动画；开局 Scenario 自身有 6 个 spawn 定义，实际 LevelTester 以其名录及世界锚点为准，避免两者相加重复计数。荒村 Blueprint 有 **98 个 objectPlacements**：22 房间（19 normal wood、2 medium wood、1 medium stone；用途 20 Residential、1 Medical、1 Prison）、27 床、16 中树、5 大树、9 矿、6 农田、4 药田、4 修炼垫，另有核心／洞口／储藏室／泉等。发布 Surface 有 103 个 `sitePlacements`、12 个 `factionFlags`、22 个 `sitePlaces`；后两者是标记使用对象数，不是独立原画数。13 个建筑定义含 6 种房间等级/材料组合，但当前地图只使用其中 3 种；房间始终是通用房体＋等级＋材料＋用途，医疗/囚禁仅用途。房间和床的稳定 ID、门洞、阻挡格、床边使用点、交互与关押逻辑都不能由整图替代。

273 共 **55 个去重资产/表现族：P0 39、P1 12、P2 4**。这是登记行数，不是立即需要生图的张数。当前使用量包括上述 25 人、27 床、21 树等；去重后人物为 **1 个共用身形/动作框架＋少量识别外观**，床为 **1 个床体＋用途色/小标识**，工作为 **1 个通用 Work 片段**服务耕作、采药、伐木、采矿、施工五种玩法。登记中需新画的基础基形/模块、服装与状态变体、共用动画片段、程序效果分别记录在“交付形式／复用关系”列，方向/帧数未拍板，**不能把 55 行折算为 55 张 PNG 或 55 套动画**。首批只取下文少量样本，P1/P2 不阻碍样机。

按交付形式再拆：**40 个静态/模块/图集资产族**（17 模块、13 单图、10 图集），**3 个共用动画片段族**（Idle/移动、Work、攻击），**7 个程序效果族**，**5 个参考图族**。这是互斥登记行统计，其中已有灰盒、可复用与待制作混在各组，不代表 40 张必画图。变体槽按当前对象可核实的至少有主角三人识别、房间当前三种等级/材料组合、三种房间用途/床色、树 S/M/L 三尺寸；到底需要多少独立切片/配色，待风格和接入样本确认后填写到对应行，现阶段不能虚报制作件数。

现有 `Assets/Art` 共 16 张 PNG，全部能追到至少一个 `Assets/Prefabs` 中的 Sprite GUID 引用，24 个 Prefab 保留；但 `MapLayoutPrefabResolver` 在 Editor 通过 `AssetDatabase.LoadAssetAtPath` 加载 `MapKindCatalog` 的 Prefab，Build 路径会返回 false，而 `EntityViewSpawner` 当前给人物使用 `HostSpriteFactory.UnitSprite()`，并非按名录加载旧的六个人物 Prefab。`HostSpriteFactory` 找不到 `Resources/HostSprites/*` 时生成程序 Sprite；当前未找到该目录下 PNG。故旧 PNG/Prefab **可继续作为灰盒和样本对照**，不能笼统写成“当前25人和整张地图都已用它们正式呈现”。旧墙、矿堆、树、垫等 Prefab 分别借道路、林地、灵地占位图，需在后续样本验证中逐项确认正式映射。人物头像 `HostCharacterRelationUi.TryResolveCharacterPortrait` 目前直接返回 false；设定图不能登记成已挂接头像。

## 已确认的双层美术标准与待验证规格

- **场景／建筑／地表：**总体目标参考《鬼谷八荒》的美术气质，采用**国风平涂＋轻纹理＋清晰轮廓＋顶视角适配**；相对精美，但必须服务俯视玩法中的房间门洞、资源状态和角色读取。不走纯像素风、高写实厚涂或过密细节。这里确认的是方向，不是照搬已有作品的具体素材。
- **双层精度：**实时场景人物采用简化国风角色表现，低细节、强复用、少动作差分；不强调面部五官/表情，重点是轮廓、服装、发型和身份辨识，以适应同屏多人。角色立绘可明显更精细、更有表现力，质量目标可接近《鬼谷八荒》人物立绘的观感；立绘不是运行人物 Sprite，也不能以其精度要求倒推 25 套实时动画。
- **动作：**基础 Idle/移动共用结构；伐木、耕作、采药、采集/采矿、施工统一复用一个 Work 动作，靠工具、目标反馈、小图标辨别；搬运尽量复用基础动作，只允许待样本验证的轻微姿态差分，并显示**实际被搬运者的外观**；攻击保留独立动作表现。受击优先闪白/轻抖；睡眠、弥留、尸体优先静态姿态或简单变换，不追求复杂逐帧。表现共享不合并正式玩法规则。
- **待确认／待样本验证：**实时人物最低方向数、每种动作最低帧数、LevelTester 实际缩放下的像素密度与运行尺寸、搬运是否需要轻微独立姿态差分、AI 原图与后续外包源文件的存放规则。具体色板、光源、描边和过滤方式在样本中核对；不可先把旧 32px / 4 方向写成合同规格。
- 与当前接入相关的固定约束：角色 Sprite 的 Pivot 要对应移动 View 的落脚点，所有帧保持一致；人物与被搬运者叠层需要稳定挂点和排序；透明背景不得污染轮廓；地面和墙角要无缝拼接；房间图必须保留真实门洞、室内家具和可破坏墙格；床的占地、床边合法使用点、枕端和 `RoomUsage` 染色/标识不可因换图错位；世界标记需在不同镜头缩放和加载边界可读。动画事件如未来用于正式命中/工作时点，应从既有玩法时序映射，不能用图片帧触发改写 Core 结算。
- 运行交付可能是 Sprite、图集/动画片段、Prefab 的 `SpriteRenderer`、IMGUI 样式纹理、材质或程序粒子，按 273 的接入口逐项核。没有找到的写“待确认”。名称、任务文字、库存数量、忠诚和生命数值保持可编辑文本，不能烘焙进背景图。开发 Debug HUD、作弊页暂缓美化。

## 生产、接入与替换责任

需求由 Development 根据正式配置/玩法入口登记并给每项稳定 AssetID，Architecture 只在触及已冻结接口时审查；制作人确定范围、规格、风格并作运行验收；AI 首版或外包作者按批准规格交付；Development/美术接入人员检查切片、透明度、Pivot、排序、Prefab/材质/动画引用后接入。Narrative 提供角色辨识/世界语义，不代替工程结构决策。

登记状态只用：**待确认 → 待制作 → 待接入 → 已接入待验 → 已验收**，另有暂缓/废弃；品质阶段单列 **灰盒／AI首版／人工正式版**。每次产出更新来源与授权、版本记录、文件路径；接入时写明被哪个 Prefab、SpriteRenderer、UI、配置映射或程序效果调用；制作人人工验收后才改验收状态。AI 首版即使被验收，也仍可在同一 AssetID 下被人工正式版替换。

替换时保留 AssetID、人物/房间/床等玩法身份和交互规则。复用原 `.meta`/GUID 仅是避免引用变化的一个条件；仍必须复核 Sprite 切片名称/尺寸、Pivot、PPU、动画片段与 Controller、Prefab 层级、挂点、材质/Shader、排序和运行状态刷新。若需要变更这些接口，先更新 273 的规格/接入方式并重新进行样本接入验收，不能承诺“直接覆盖 PNG 必然无痛”。运行资源沿用既有 `Assets/Art`、`Assets/Prefabs` 布局；原始生成图、提示词、外包源文件及授权证据与运行资源分开存放/登记，位置待团队确定。本轮不创建 `AI`/`Final` 平行引用目录，不下载字体或第三方素材，不调用付费 API；订阅不等于 API 额度。

统一提示词模板只保留结构：`[AssetID] + [对象/用途] + [已确认国风方向及待样本验证的视角/比例/色板] + [轮廓与状态差分] + [透明背景/拼接/Pivot约束] + [禁止文字/水印/多余部件] + [参考图/版本/来源与授权]`。未经首批样本验证，不批量展开提示词。

## 样张 → 小批接入 → 批量制作（均未开始）

**第一步只做两张视觉参考**：A. 一张综合场景风格样张（`ART-REF-001`），在同一构图中展示普通实时人物、木质房间/门洞、共用床、树与地表，验证国风平涂、轻纹理、清晰轮廓和俯视可读性；B. 一张与该场景人物对应的精细立绘样张（`ART-REF-002`），验证双层精度和角色气质一致。两张都只是风格参考，**不直接拆图当运行 Sprite，不把登记状态改成已接入/已验收**。首批不是全量 P0 资产生成。

**第二步在样张通过后**，以现有 273 的 AssetID 拆出少量独立素材子件及版本：普通实时人物（可附一个通用 Work 参考）、木质普通小房的地板/墙/墙角/门洞、共用床及医疗/牢房用途标识、一棵树及简单受损/砍伐反馈。接入 LevelTester 的一小片场景，检查实际缩放、路径和门洞、床用途切换、人物辨识及工作/资源反馈。样张外观和运行切片分别登记来源与状态，玩法对象身份及房间/床位规则不变。**小批接入经制作人人工验证后，才按批次补齐 P0**；不要求制作人重新手工列完整资产表。

**后续批量任务的最低记录**：选中的 AssetID 与子件、版本；已经确认的风格参考图和提示词版本；本批目标数量、候选数量与成本上限；原始生成图与处理后的运行资源分别存放。每批按 AssetID/子件/版本生成候选总览图供制作人选图，失败保留原因与重试记录，已成功的候选不被重复运行覆盖；只有用户选定后才处理、接入。生成成功不等于资产验收，接入及人工验收分别更新 273，再同步导出查看版。当前不实现批量生图平台，不绑定付费服务，不保存 API Key，也不自动发起付费生成。

## TSV 真源与 XLSX 查看版

`273-current-art-asset-register.tsv` 是**唯一可编辑的资产登记真源**，保持 UTF-8 with BOM、Tab 分隔。相邻的 `273-current-art-asset-register.xlsx` 由 `tools/export-art-register.mjs` 单向生成，只供筛选查看，不能在 Excel 查看版单独维护进度或反向覆盖 TSV。第一张“美术清单”展示关键状态，第二张“工程明细”完整保留全部字段；页内记录源相对路径、UTC 导出时间和源字节 SHA-256。不存在的图片不提供缩略图或链接。

每次修改 TSV 的**同一次任务完成步骤**是：保存带 BOM 的 TSV → 在仓库根目录运行 `node tools/export-art-register.mjs` → 由脚本回读 XLSX 核对 ID 唯一且集合/顺序一致、两页字段映射、完整明细、统计、中文和源校验值 → 确认 TSV 与 XLSX 同步出现在工作区。行数和 P0/P1/P2 数量从当次 TSV 计算，不写死。脚本使用本机 Codex 工作区依赖中的 `@oai/artifact-tool`；环境不同可用 `CODEX_WORKSPACE_NODE_MODULES` 指向该依赖的 `node_modules`。如果 Excel 占用输出文件而不能替换，关闭工作簿后重试；旧 XLSX 保留，失败不算导出完成。

仍待制作人拍板/样本验证的事项：**①实时人物最低方向数；②每种动作最低帧数；③LevelTester 实际缩放下的像素密度/运行尺寸；④搬运是否需要轻微独立姿态差分；⑤AI 原图与后续外包源文件的存放规则。**
