## 已确认的双层美术标准与待验证规格

- **正式视角与场景：**采用**正俯视**。场景整体为**国风修仙村落**，参考制作人已确认样张的整体气质和《鬼谷八荒》的国风观感，使用水墨淡彩、国风平涂、轻纹理、清晰轮廓及适度修仙氛围。村落保留真实生活气息，同时可呈现灵泉、灵药田、灵矿、修仙旗帜、石碑、法阵、灵气装饰等视觉语言；这些是风格方向，不代表每项都已有玩法定义或本批制作任务。不是纯中式田园或纯世俗农庄，也不照搬参考作品具体素材。内容可以丰富，但笔触要概括，避免高密度碎细节、纯像素风和高写实厚涂。
- **房屋开面式：**所有房屋默认可见室内，不使用完整遮挡屋顶，也不使用明显高台、楼梯或门前抬升地基。正俯视下要能直接看见人物、床、家具及室内状态；地板、墙、墙角、门洞继续按真实结构拆分，不能用一张整图覆盖门洞、床位、可破坏墙格。房间等级、材料、用途与床位玩法身份、通行和交互规则不因表现调整而改变。
- **双层精度：**实时场景人物采用简化国风角色表现，低细节、强复用、少动作差分；不强调面部五官/表情，重点是轮廓、服装、发型和身份辨识，以适应同屏多人。角色立绘可明显更精细、更有表现力，质量目标可接近《鬼谷八荒》人物立绘的观感；立绘不是运行人物 Sprite，也不能以其精度要求倒推 25 套实时动画。
- **动作：**基础 Idle/移动共用结构；伐木、耕作、采药、采集/采矿、施工统一复用一个 Work 动作，靠工具、目标反馈、小图标辨别；搬运以基础动作加挂接/背负表现为主，允许轻微姿态差分，并显示**实际被搬运者的外观**；轻差分是否需要独立片段仍待样本验证。攻击保留独立动作表现。受击优先闪白/轻抖；睡眠、弥留、尸体优先静态姿态或简单变换，不追求复杂逐帧。表现共享不合并正式玩法规则。
- **当前部件样机待人工验证：**逻辑四方向与正/背/侧、侧向镜像已确认，具体分层部件、非对称例外、运行像素密度/比例、骨骼脚点、Carry挂点/层级、SleepBed/SleepGround姿态、动作时长/轨道/循环/混合、版本/授权/导出格式、同屏性能与Build加载仍待验证。Unity部件动作不设旧逐帧最低帧数。ArtSource分区、正俯视和开面房屋保持。
- 与当前接入相关的固定约束：角色 Sprite 的 Pivot 要对应移动 View 的落脚点，所有帧保持一致；人物与被搬运者叠层需要稳定挂点和排序；透明背景不得污染轮廓；地面和墙角要无缝拼接；房间图必须保留真实门洞、室内家具和可破坏墙格；床的占地、床边合法使用点、枕端和 `RoomUsage` 染色/标识不可因换图错位；世界标记需在不同镜头缩放和加载边界可读。动画事件如未来用于正式命中/工作时点，应从既有玩法时序映射，不能用图片帧触发改写 Core 结算。
- 运行交付可能是 Sprite、图集/动画片段、Prefab 的 `SpriteRenderer`、IMGUI 样式纹理、材质或程序粒子，按 273 的接入口逐项核。没有找到的写“待确认”。名称、任务文字、库存数量、忠诚和生命数值保持可编辑文本，不能烘焙进背景图。开发 Debug HUD、作弊页暂缓美化。

- `ArtSource/References/` 保存已确认的整体风格参考；`ArtSource/Batches/<批次ID>/Originals/` 保存原始字节副本；`Candidates/` 仅在选图后保存可追溯加工候选；`Previews/` 和 `manifest.json` 保存检查与映射记录。`ArtSource` 位于 Unity `Assets` 之外，不是第二套运行资源目录。

- 整理工具不移动、删除或改写 Inbox 原图；重复运行按内容哈希跳过既有文件。同名不同内容不得覆盖，相同内容不得重复入库。
- 图片选定、子件加工、Unity 接入和 LevelTester 人工验收分别记录。未经制作人选定，不确定最终方向数、帧数、PPU、运行尺寸或 Pivot，不套用历史像素风规格，也不按连通区域强制拆分多人图或组合图。

## 生产、接入与替换责任

需求由 Development 根据正式配置/玩法入口登记并给每项稳定 AssetID，Architecture 只在触及已冻结接口时审查；制作人确定范围、规格、风格并作运行验收；AI 首版或外包作者按批准规格交付；Development/美术接入人员检查切片、透明度、Pivot、排序、Prefab/材质/动画引用后接入。Narrative 提供角色辨识/世界语义，不代替工程结构决策。

登记状态只用：**待确认 → 待制作 → 待接入 → 已接入待验 → 已验收**，另有暂缓/废弃；品质阶段单列 **灰盒／AI首版／人工正式版**。每次产出更新来源与授权、版本记录、文件路径；接入时写明被哪个 Prefab、SpriteRenderer、UI、配置映射或程序效果调用；制作人人工验收后才改验收状态。AI 首版即使被验收，也仍可在同一 AssetID 下被人工正式版替换。

替换时保留 AssetID、人物/房间/床等玩法身份和交互规则。复用原 `.meta`/GUID 仅是避免引用变化的一个条件；仍必须复核 Sprite 切片名称/尺寸、Pivot、PPU、动画片段与 Controller、Prefab 层级、挂点、材质/Shader、排序和运行状态刷新。若需要变更这些接口，先更新 273 的规格/接入方式并重新进行样本接入验收，不能承诺“直接覆盖 PNG 必然无痛”。运行资源沿用既有 `Assets/Art`、`Assets/Prefabs` 布局；原始生成图、提示词、外包源文件及授权证据放入 `ArtSource` 并与运行资源分开登记。本轮不创建 `AI`/`Final` 平行引用目录，不下载字体或第三方素材，不调用付费 API；订阅不等于 API 额度。

统一提示词模板只保留结构：`[AssetID] + [对象/用途] + [已确认正俯视/开面房屋/国风修仙村落方向及待样本验证的比例/色板] + [概括笔触、轮廓与状态差分] + [透明背景/拼接/Pivot约束] + [禁止文字/水印/多余部件] + [参考图/版本/来源与授权]`。未经运行样本验证，不批量展开提示词。

## 原筹备顺序：样张 → 小批接入 → 批量制作（首批候选生产已由上文新指令调整）

**第一步只核两张视觉参考**：A. 一张综合场景风格样张（`ART-REF-001`），在正俯视构图中展示普通实时人物、开面木质房间/门洞、共用床、树与地表，并体现生活村落与修仙氛围并存；B. 一张与该场景人物对应的精细立绘样张（`ART-REF-002`），验证双层精度和角色气质一致。制作人已确认的样张气质可作为方向依据；具体文件和两张参考的逐项状态仍需登记核实。参考图**不直接拆作运行 Sprite，不因风格确认而改成已接入/已验收**。首批不是全量 P0 资产生成。

**第二步在样张通过后**，以现有 273 的 AssetID 拆出少量独立素材子件及版本：普通实时人物（可附一个通用 Work 参考）、木质普通小房的地板/墙/墙角/门洞、共用床及医疗/牢房用途标识、一棵树及简单受损/砍伐反馈。接入 LevelTester 的一小片场景，检查实际缩放、路径和门洞、床用途切换、人物辨识及工作/资源反馈。样张外观和运行切片分别登记来源与状态，玩法对象身份及房间/床位规则不变。**小批接入经制作人人工验证后，才按批次补齐 P0**；不要求制作人重新手工列完整资产表。

**后续批量任务的最低记录**：选中的 AssetID 与子件、版本；已经确认的风格参考图和提示词版本；本批目标数量、候选数量与成本上限；原始生成图与处理后的运行资源分别存放。每批按 AssetID/子件/版本生成候选总览图供制作人选图，失败保留原因与重试记录，已成功的候选不被重复运行覆盖；只有用户选定后才处理、接入。生成成功不等于资产验收，接入及人工验收分别更新 273，再同步导出查看版。当前不实现批量生图平台，不绑定付费服务，不保存 API Key，也不自动发起付费生成。

## 固定的文件级清单交接

任何美术新增、修改、删除、切片、Unity 导入、Unity部件换皮或动画更新任务，收尾时在仓库根目录运行 `python tools/export-art-inventory.py`。脚本扫描 `ArtSource`（排除自身生成的 `Reports`）及 `Assets/Art`，按文件记录项目相对路径、大小、SHA-256、AssetID、批次/版本、273 的目标技术路线、文件角色、可核实的 Unity 静态引用及清理判断；输出 [current-art-inventory.tsv](../../ArtSource/Reports/current-art-inventory.tsv) 和 [latest-art-change-report.md](../../ArtSource/Reports/latest-art-change-report.md)。两者是可直接上传 ChatGPT 的 UTF-8 文本，不含图片二进制。

首次运行没有上一快照时只建立基线，历史新增/修改/删除记未知；后续从上一份清单按路径和哈希比较。文件级清单不代替 273 的资产族制作/接入/验收状态；缺少证据写“未知”，同哈希、位于 `Resources` 或存在 `.meta` 都不单独证明实际游戏已验收。删除前须另核 manifest、273、加工脚本和 Unity GUID/资源加载路径，不能由脚本的重复统计自动删除。

## TSV 真源与 XLSX 查看版

`273-current-art-asset-register.tsv` 是**唯一可编辑的资产登记真源**，保持 UTF-8 with BOM、Tab 分隔。相邻的 `273-current-art-asset-register.xlsx` 由 `tools/export-art-register.mjs` 单向生成，只供筛选查看，不能在 Excel 查看版单独维护进度或反向覆盖 TSV。第一张“美术清单”展示关键状态及推荐技术路线，第二张“工程明细”完整保留原17列与新增4列共21字段；页内记录源相对路径、UTC 导出时间和源字节 SHA-256。不存在的图片不提供缩略图或链接。

每次修改 TSV 的**同一次任务完成步骤**是：保存带 BOM 的 TSV → 在仓库根目录运行 `node tools/export-art-register.mjs` → 由脚本回读 XLSX 核对 ID 唯一且集合/顺序一致、两页字段映射、完整明细、统计、中文和源校验值 → 确认 TSV 与 XLSX 同步出现在工作区。行数和 P0/P1/P2 数量从当次 TSV 计算，不写死。脚本使用本机 Codex 工作区依赖中的 `@oai/artifact-tool`；环境不同可用 `CODEX_WORKSPACE_NODE_MODULES` 指向该依赖的 `node_modules`。如果 Excel 占用输出文件而不能替换，关闭工作簿后重试；旧 XLSX 保留，失败不算导出完成。
