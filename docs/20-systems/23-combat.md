# 战斗

> 状态：草稿 | 优先级：P0 | 最后更新：2026-07-30
> 上级：`docs/00-project/00-overview.md`

## 1. 这个系统解决什么问题

战斗是检验角色构筑与境界能力是否成立的考场。它必须能表达"高境界压制低境界"的爽感，同时不能退化成纯数值对撞，也不能变成需要高速操作的动作游戏。

## 2. 当前方向

- **2D 视角**，不转 3D 战场。
- **暂停即时（RTwP）**：时间实时流逝，玩家可随时暂停下达指令。
- 直接控制少量修士组成的小队，角色有不同定位、技能、装备与功法。
- 初始三人形成近战承伤、远程输出、治疗辅助的互补关系。
- **战力悬殊且结果明确时允许自动结算**；势均力敌或关键战役进入手动战斗。
- 境界能力要改变战场规则，例如飞行带来空地分层，护体灵力使凡兵难以造成有效伤害。

重点不是操作速度，而是暂停决策、站位、目标选择、技能组合与境界能力的正确使用。

## 3. 自动结算的要求

- 结算结果必须**可溯源**：玩家能看到"为什么赢／为什么输"的计算链。
- 自动结算不应产生手动战斗打不出的结果（避免玩家为最优解而反复手动）。
- 悬殊判定的阈值需要可配置，不写死在代码里。

## 4. 与其他系统的接口

- 输入：角色属性、境界能力、功法与装备、地形、参战人数、士气或补给。
- 输出：伤亡、伤势、缴获、据点归属变化、业力与关系后果。

## 5. 未决问题（**影响原型形态**）

- [ ] 采用连续即时暂停，还是短回合／行动冷却式表现？（后者实现成本更低、更易平衡）
- [ ] 战场规模上限是多少个单位？凡人军队如何参战——作为单位还是作为战场修正？
- [ ] 空地分层如何在 2D 视角下清晰表达？
- [ ] 是否需要阵型与站位系统，还是仅有前后排抽象？
- [ ] 战斗中时间是否与世界时间同步流逝，还是进入独立的战斗时间？
