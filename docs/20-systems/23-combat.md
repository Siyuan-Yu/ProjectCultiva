## 1. 这个系统解决什么问题

战斗是检验角色构筑与境界能力是否成立的考场。它必须能表达"高境界压制低境界"的爽感，同时不能退化成纯数值对撞，也不能变成需要高速操作的动作游戏。

## 2. 当前方向

- **2D 视角**，不转 3D 战场。
- **玩家实战 = 同源独立 Encounter**：遭遇准备 → 战中 → 胜利可结束 → 可选的一次收尾 → 最终结算 → 各回战前世界锚点。见 ADR-0033／`21` §10。
- **RTS 式实时行动**（战术层）：单位实时移动与交战。
- **战术可暂停**：暂停状态下下达战术指令；**不**推进战略 WorldTick。
- 修士可以释放技能、使用法宝、移动、攻击并互相配合。
- 战力悬殊或玩家选择时允许自动结算；关键战斗进入手动操作。

重点不是操作速度，而是暂停决策、站位、目标选择、技能组合与境界能力的正确使用。

<a id="encounter-confirmation"></a>
### 2.1 统一遭遇窗口

- 所有新的玩家实战都在第一击／第一发攻击弹道发出或生效前暂停，只显示一次明确遭遇窗口。已有战争、私人仇敌、我方主动或敌方主动都不例外。
- 人物遭遇的统一入场 UX 为：`Pending tactical confirmation → Preparing → ReadyToStart → explicit Start Battle → Active`。`ReadyToStart` 只属于 Host presentation：Core `CharacterEncounterState` 已经是 `Active`，但 `CharacterEncounterUI` 仍持有 ModalHardPause 和输入锁；玩家点击“开始战斗”前不设置初始目标、不执行入场攻击 callback，也不推进战术时间、关系介入或 AI。
- 右键敌对目标直接提交攻击意图；远距离赶路阶段不停表，真正接战才进入准备。主动方可取消尚未实施的攻击；敌方袭击已经成立时不能靠关闭窗口免战。
- 初始双方仅为发起者与目标各自当前小队；第三队不因共同袭击／守备身份自动进入初始名单，范围内第三方依 §3.1 候选规则处理。后续合法攻击不逐刀确认；扩大战争仍确认新增后果。

### 2.2 同源独立战场

- 战场使用交战地点**当时**的地形、通路、静态／动态建筑及门、墙、桥、议政厅状态，不是裸地形或随机竞技场。可简化装饰，但关键结构、可达性和参战者相对位置必须真实。
- 范围按实际接战地点的有效 Site 选择：Site 内以唯一议政厅／旗的真实位置为中心，大小／形状直接使用当前核心控制范围；当前 Level 1 为 150×150 cells，在 Main Surface 解析为 4.2×4.2 world（3×3 chunks）。重叠选唯一有效 Site，不合并。无有效 Site 则为接战点中心的独立 Wilderness Encounter 范围，当前仍为 500×500 cells／14×14 world／约10×10 chunks。准备时固定，战中不扩缩；不以 HomeSite、Army marker、Hex、相机／3×3 窗口代替。
- 非参战居民不因复制建筑而全体入场；旧“原地战斗时全体附近居民局部避难”不再是 V1 必做。
- 连续探索 `WorldPosition` 与战术临时坐标分离；战术移动不提交成主世界旅行。
- 独立战场完整 materialize 后先显示顶部“开始战斗”条且保持全场暂停。读取一个仍处于 Core `Active` 的 CharacterEncounter 也走同一 start gate；读取 `ReadyToEnd` 直接恢复战后可结束状态。已存在战场内追加 SiteCore objective 不重新加载场地或再次显示 start gate。

## 3. 战斗规模

**核心是小队级修士战斗。**

明确不做：

- 数千人同时实时操作的大型战场。
- 全面战争级的实时单位微操。

大型势力战争以后可通过算法结算、战报、战略面板等方式表现，不要求玩家在同一战场上同时指挥上千单位。凡人军队如何参与小队战场，仍见未决问题。

<a id="encounter-participation"></a>
### 3.1 参战、关系援军与一次收尾

- 初始仅发起者当前小队与目标当前小队。同队不随机缺席，但按每人的真实位置、生命状态和会话占用验证；不能从共同 Army 锚点搬入远方成员。不能合法纳入固定战场时入场前报明原因，不漏人、不扩场。
- 第三方不因同势力、守备、附近或同／邻 Hex 自动进入，不使用 OptionalFriendly／Hex support。资格在介入前判断，不使用 Renderer、相机或 loaded Chunk 替代真实空间。旧 Hex 支援是 CW-U2B 待替代兼容。
- 开战时只查询本场固定范围内的有限关系候选。候选暂不显示、不可攻击、不计胜负／战报；范围外者本场不得追加候选，不递归朋友网络。双方对称，按人物／小队有限判断，不逐帧重抽，不靠逐成员抽签放大整队概率。
- 决定、已判定、待到场、已加入须持久化，读档不重抽／重复加入。正式加入以明确事件追加实际名单，同步显示、攻击、控制资格、胜负与战报；场次身份固定而名单可追加。初始位置和返回锚点来自该候选本人，不在边缘／玩家背后任意刷新。
- 临时助战不改变永久小队、玩家控制、背包或势力身份；最多一次最终结算前续战。未决定候选不无限阻止结束，最终结算后不得再加入。
- 实施顺序见 ADR-0035：CW-U2A 单人闭环、CW-U2B 多人及初始资格、CW-U3 有限介入。替代原 CW-06／范围外远援排序。
<a id="encounter-lifecycle"></a>
### 3.2 遭遇生命周期与可保存状态

| 状态 | 允许行为 | 退出条件 |
|---|---|---|
| 遭遇准备 | 暂停全部相关推进；确认新战斗及适用政治后果；构建场地后停在 Host ReadyToStart | 玩家明确点击“开始战斗”，或取消尚未实施的我方主动攻击 |
| 战中 | 本场战斗时间推进；合法攻击不逐刀弹窗；可暂停确认第三方建筑战争后果 | 正式接管完成或本次有效敌人被打倒，进入“胜利可结束” |
| 胜利可结束 | 可立即结束，或继续本场内实际接管等短期交互 | 玩家结束，或进入既定有限收尾 |
| 一次收尾 | 最多一次；先暂停告知；沿用现有生命、消耗和位置状态 | 收尾解决；标记本场收尾已使用 |
| 最终结算 | 暂停局部时间；提交唯一战果和奖励；禁止生产、建设或长期修炼 | 唯一结算完成 |
| 返回 | 各回自己的战前世界锚点；只做必要最小合法性修正 | 释放本场暂停原因并抑制同次接触立即重开 |

有限候选的已判定／未判定、已决定／在途／到场、一次收尾是否已使用、每人原锚点和唯一结算结果都属于需保存的生命周期事实。读档不得重新抽取已决定的援军、重复加入参与者或再次发放奖励；本规则只锁契约，不规定新的 RNG API。

## 4. 单 Active 战术操作语法

### 4.1 鼠标

- **左键**：选择查看目标或当前 Active 的交互目标；不获得其他同行者的直接控制权。
- **右键**：移动、攻击、互动。

同一时刻只直接控制一个 Active；Followers 和临时援军由 AI 执行本场职责。旧框选、多选编队和分别下令只属于历史 RTS Prototype，不是当前产品权限。

### 4.2 键盘

- **1–6**：释放当前角色装备的技能。

技能与法宝通过快捷键选择，再指定目标或位置。

### 4.3 操作原则

- 基础攻击与追击可由 AI 自动执行，玩家可设置行为姿态。
- 暂停后可检查局势并给当前 Active 下令；普通同行者继续由 AI／Policy 决策。
- 不要求走 A、极限拉扯、每秒多次操作；暂停是正式机制，不是辅助功能。

本作不是传统高 APM RTS；暂停用于当前 Active 的战术决策，不扩张为对所有在场角色的直接控制。

## 5. 技能系统

### 5.1 学习与装备

- 角色**可以学习大量技能**（策划层不设硬性“学完即满”的上限；若未来因体验需要设软上限，再另议）。
- **战斗中最多装备 6 个技能**，对应快捷键 1–6。

学得多、带得少：深度来自选择与搭配，不来自战斗栏无限膨胀。

### 5.2 自动技能系统

技能支持自动释放设置。玩家可为角色选择：

| 模式 | 含义 |
|---|---|
| 手动 | 完全由玩家控制释放 |
| 半自动 | 角色自动释放玩家允许的技能 |
| 自动 | AI 根据规则释放技能 |

具体 AI 逻辑、优先级、目标选择与打断规则**以后设计**，本阶段只锁定三种模式存在。

## 6. 普通攻击随境界变化

境界差异要体现在**攻击方式变化**，不只是伤害数字。

| 阶段 | 普通攻击方向 |
|---|---|
| 凡人／感应境 | 徒手、武器、弓箭等近距离／常规肉身战斗 |
| 炼气 | 灵力强化攻击、基础灵力攻击 |
| 筑基 | 召唤**斗气纱衣**后，普攻切换为远程灵力外放（伤害／攻速与近战相同；射程随境界配置） |
| 更高境界 | 普通攻击的范围、控制距离与影响范围继续提升 |

**已落地竖切（2026-08-16／17）：** 见 [134](../40-process/134-spirit-veil-ranged-normal-attack-2026-08-16.md)。筑基 **F2**／底栏「纱衣」召唤（固定灵力开销）；空灵力／交战结束自动卸下；远程普攻用**统一青色弹道**（飞行光核→命中爆闪）。

**已落地竖切（2026-08-20）：** 见 [142](../40-process/142-auto-battle-incap-corpse-2026-08-20.md)。HP 归零→**弥留**（`Incapacitated`）；再受击→死亡+**尸体**（普通人约 2 游戏日 decay）；大地图自动战有伤亡结算与「战胜时直接击杀」勾选；底栏／详情 UI 左上角显示弥留／尸体角标。

普通攻击的具体动画、更高境界射程与开销随推进细化。

## 7. 战斗资源

### 7.1 生命值

代表肉身状态。

**生命归零：进入重伤，不是立即死亡。**

### 7.2 灵力值

独立于修为。用于：

- 技能释放
- 灵力护体
- 飞行
- 特殊能力

### 7.3 灵力护盾／灵力防护

不是装备盾，而是一种额外生命层。

战斗承伤顺序：

```
灵力护盾／灵力防护
        ↓
     肉身生命
```

灵力护盾如何由功法、境界、技能生成与恢复，细则**待确定**；与“灵力值本身被优先消耗”的既有表述需在数值阶段统一成一套可读规则。

## 8. 神识在战斗中的作用

神识影响：

- 技能控制能力
- 法术精度
- 法宝控制数量与上限
- 精神类能力对抗

示例（规则形态，非定稿数值）：低神识只能御一把飞剑，高神识可御多把；复杂法术的目标数与范围可随神识提高。

### 8.1 元婴以后的神魂战斗

元婴及以后可进行神魂层面的战斗。

高神识修士可对低境界、低神识目标产生压制，例如降低：

- 技能效果
- 灵力恢复
- 战斗能力

压制幅度、对抗方式与是否受因果／道心约束，**待确定**。详见 `22-realms-and-abilities.md` 与 `2B-attributes-and-affinity.md`。

## 9. 境界能力如何改变战斗

境界不是加数值，而是增加可下达的命令与改变战场规则。

- 感应境：尚无修士战斗能力，只能依靠肉身属性；情报优势来自神识而非境界本身。
- 炼气：灵力资源、基础法术、灵力护体；真正拥有修士战斗能力，但不是巨大跃迁。
- 筑基：控制外物与灵气——法器／法宝、灵气附武、驭器、远距离灵力攻击。
- 金丹：力量外放改变战场——内丹、灵气外放／铠甲式护体；真正飞行（讨论中）。
- 元婴：生命形式改变——出窍、神魂战斗、第二生命、神识压制。
- 更高境界：神识领域、规则力量、踏空、空间能力等，见 `22`。

战力影响排序见 `2D-manuals-arts-and-equipment.md`：境界 > 功法 > 斗技 > 角色属性 > 装备。

角色属性会改变同一技能的实际表现：神识决定控制上限，灵根决定对应属性威力，掌握程度决定发挥到几成，心境影响越级用力时的稳定性。

## 10. 战斗结束、重伤与击杀

### 10.1 重伤

生命归零后进入**重伤状态**，不是立即死亡。

默认设置：

- **“不攻击重伤敌人”默认开启。**
- 单位默认不会继续攻击已重伤的敌人。

玩家可以关闭该设置，选择主动击杀。

### 10.2 重伤后的互动

重伤敌人可能触发：

| 类型 | 示例 |
|---|---|
| 求饶 | 交出物品，请求放过 |
| 威胁 | 提醒玩家背后有强大势力 |
| 交易 | 提供信息或资源 |

### 10.3 放过与击杀的后果

选择放过：敌人离开战场。之后可能：

- 感恩
- 复仇
- 产生新的关系事件

选择击杀：获得更确定的消除威胁，但会进入**因果／道德体系**，并可能触发仇怨与江湖关系后果。详见 `28-jianghu-relations.md` 与 `29-karma-and-consequence.md`。

击杀不是单纯“邪恶”，战场杀敌与滥杀无辜的因果权重不同；规则方向见 `29`。

具体触发概率、选项池与势力报复强度**待确定**。

## 11. 战利品

击败或搜刮敌人后，获得其**实际携带的物品**，而不是抽象掉落表随机生成与人设无关的奖励。

可能包括：

- 武器
- 丹药
- 妖兽材料
- 功法
- 斗技
- 特殊物品

掉落根据敌人实际携带决定。敌人为什么携带这些东西，应能被玩家理解。

## 12. 战斗与世界的关系

> **2026-08-21** 以 [ADR-0023](../40-process/43-decisions/ADR-0023-manual-encounter-freezes-worldtick.md) 为准。

- 战略接战进入 **Encounter LocalMap**（Modal）；不是「世界继续跑的同时性战场」。
- `BattleOffer` 起至 Encounter Resolve：战略 **WorldTick 冻结**；AutoResolve 亦不推进 Tick。
- 遭遇中的单 Active 战术控制与局部暂停只作用于本场；同行者和援军由 AI／Policy 行动，不提供框选或多单位逐步命令。恢复开战前 pause／倍速仅在 Resolve 之后。
- 参战者分别保存战前世界锚点；关系／守备介入只从有限真实候选按状态、职责与可达性判断，禁止靠“加入战斗”战略瞬移。
- 普通道路／野外遭遇 Resolve 后销毁实例；不默认「回旧战场」。

<a id="encounter-return-anchors"></a>
### 12.1 回战前世界锚点，保留战果（2026-09-12，最高优先级）

- 最终结束时，每名主控、队友、敌人、守备和关系援军都回到自己为本场行动前的世界空间身份与精确位置；不回玩家脚边、不回 Hex 格心，也不保留战术最终坐标。
- 只恢复空间锚点。生命、伤势、弥留／死亡、消耗、装备／库存、关系、宣战、建筑损伤、拆旗和接管全部保留，并且只提交一次。
- 死者在自己的原世界锚点形成唯一尸体；战利品、尸体和容器不得复制。非法原点只做最小合法性修正。
- Active 中途更换时，每个人仍回自己的原位置，当前控制身份不回滚；按恢复坐标和当前控制重新解析 CurrentSite。
- 结束后抑制同一次接触立即重开，但不清除全局战争或私人敌对。旧 ADR-0023“统一留在 BattleAnchor”由 ADR-0033 部分替代。

<a id="encounter-capture-victory"></a>
### 12.2 战场接管、胜利资格与最终结算

- 战场包含议政厅时，主控或己方派出修士可按正式攻破与交互条件在场内完成接管；议政厅不可拆，防御被击破不等于删除实体。
- **正式接管完成 OR 本次有效敌方战斗人员被打倒**，任一成立即可获得“结束”资格。取得资格后可继续本场内接管等动作；打倒人物但未接管不会自动获得土地。
- 接管结果不能因仍有活守卫而扣留；残存守备结束本次防御后可在返回世界时退却，不被自动删除、收编或清除仇恨。
- 既定有限收尾完成后只做一次最终结算；撤退、失败也不能回滚已经发生的合法伤亡、消耗、关系、建筑损伤、宣战或接管。

### 12.3 撤退与倒地同伴

- 默认整队撤退，必须满足真实合法撤离／脱离接触条件；触碰场景边缘不等于免战，仍在交战的人不算已撤走。
- 合法撤离后，可以明确列出并确认放弃无法救出的倒地同伴。V1 不附带完整俘虏／赎金系统。
- 无论带走或放弃，位置规则仍优先：双方回各自战前世界锚点并保留生命／救援结果；“留下”不表示永久停在战术倒地点，也不构成世界运输。

大型势力战争不走数千人实时微操，而走算法／战报等表现（见第 3 节）。

## 13. 第一个卡点：筑基管事弟子

- 管事弟子可以灵气附物、使用法宝与斗技、驭器短距离飞行，规则权限高于炼气角色。
- 三名炼气角色需要通过战前准备削弱他，再利用分工取胜。
- 若玩家未削弱其规则优势，战斗应明确表现出"权限差距"，而不是只表现为更高血量。

## 14. 自动结算的要求

- 结算结果必须**可溯源**：玩家能看到"为什么赢／为什么输"的计算链。
- 自动结算不应产生手动战斗打不出的结果。
- 悬殊判定的阈值需要可配置。

## 15. 与其他系统的接口

- 输入：角色属性、境界能力、功法与装备技能、地形、参战人数、士气或补给。
- 输出：重伤／死亡、伤势、缴获、据点归属变化、业力与关系后果。
