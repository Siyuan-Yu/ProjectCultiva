# 核心循环与统一时间

> 状态：主要结构已确定，数值待原型验证 | 优先级：P0 | 最后更新：2026-07-30
> 上级：`docs/00-project/00-overview.md`
> **所有其他系统都挂在这份文档定义的时间轴与指令模型上。**

## 1. 这个系统解决什么问题

角色行动、修炼、领地生产、事件推进和战斗必须能换算到**同一条游戏时间**上，否则会出现"战斗时领地停摆""修炼与探索各算一套时间"这类结构性矛盾。这个系统定义"一天怎么过"，以及玩家在其中到底在操作什么。

## 2. 指令模型：下达意图，角色自动执行

这是本作操作方式的根本定性。

- 玩家下达的是**意图**（去砍那片树、去打那三只妖兽、留在这里修炼），角色自动寻路、执行、汇报。
- **三名角色可以完全分头行动**，各自持有独立的指令队列。
- 指令可以随时追加、插队、取消、改派，一天之内没有指令次数上限。
- 玩家不需要逐帧操作，也不应该因为手速获得优势。

参照物是《环世界》那类"指派 + 自动执行"，不是《全面战争》那种战场直控。

### 推论：玩家真正在做的决策是分配稀缺时间

既然过程自动完成，玩家的乐趣就必须来自**取舍**：这个人今天去干活还是去掩护？省下的两个时辰拿去修炼还是去打听消息？这一条决定了前期所有系统的设计取向，也是 `2F-obligation-and-concealment.md` 成立的前提。

### 抽象层随规模上移

| 规模 | 玩家操作粒度 |
|---|---|
| 3 人 | 逐个下达具体指令 |
| 10 人上下 | 设定岗位与优先级，只对关键角色单独下令 |
| 30 人以上 + 多据点 | 设定政策与方针，只处理异常和重大抉择 |

这直接服务差异化 3（规模扩大时操作量不增加），三个层级共用同一套指令数据结构，只是暴露给玩家的粒度不同。

## 3. 时间粒度

### 逻辑层

- 最小时间单位 **1 Tick = 15 游戏分钟**。
- 一个游戏日 = **96 Tick**。
- 逻辑层只认 Tick，不认真实秒数。所有耗时都以 Tick 表示，便于存档、回放和可溯源。

### 表现层

玩家看到的是时辰与时段，不是 Tick 计数。

| 时段 | 时辰 | Tick 区间 | 前期的含义 |
|---|---|---|---|
| 清晨 | 卯 | 20–28 | 点名，领取当日配额 |
| 上午 | 辰巳 | 28–44 | 干活 |
| 正午 | 午 | 44–52 | 干活，可短暂休息 |
| 下午 | 未申 | 52–68 | 干活 |
| 黄昏 | 酉 | 68–76 | 交差验收，分发口粮 |
| 入夜 | 戌亥 | 76–88 | 宵禁开始，守卫巡逻 |
| 深夜 | 子丑寅 | 88–20 | 巡逻最稀疏，暗面行动的主时段 |

### 速度档位

- 暂停 / 1x / 4x / 16x。
- 1x 下约 1 Tick / 秒，一个游戏日约 96 秒。前期 20 天在不含暂停思考的情况下约 30 分钟。
- 高倍速时**不降低事件触发概率**，改为提高自动暂停的灵敏度。玩家快进是为了跳过无事发生的时段，不是为了跳过内容。

## 4. 每 Tick 的结算顺序

顺序固定，保证同样的存档与同样的操作必然得到同样的结果。这是数值可溯源的前提。

```
1. 推进时间        Tick +1，更新时辰、时段、日期
2. 角色行动        移动、采集、制作、修炼、掩护的进度累积
3. 环境与生产      资源点刷新、建造进度、领地产出累积
4. 状态变化        体力、饥饿、伤势、修为、怀疑度衰减
5. 判定与事件      配额验收、遭遇判定、巡逻检查、突破条件检查
6. 中断检查        判断是否需要自动暂停并提示玩家
```

第 3 步的领地产出**按 Tick 累积、按日结算**。玩家看到的是每日汇总，不是每 15 分钟弹一次收成。

## 5. 自动暂停

玩家不可能盯着 16 倍速看完整天，所以"什么时候把控制权交还玩家"必须明确。

**必须自动暂停：**

- 遭遇敌对单位，或战斗即将开始
- 怀疑度跨越阈值，或角色即将被撞见
- 修炼完成、突破的关键节点
- 角色重伤、濒死、中毒等严重状态
- 重要事件或抉择触发
- 全部角色的指令队列清空且无事可做

**只通知不暂停：**

- 采集、制作、建造完成
- 每日产出结算
- 普通 NPC 对话请求

两类的归属应当可由玩家在设置里调整。指令队列清空必须暂停——它意味着有角色在闲置，那是玩家的时间在被浪费。

## 6. 战斗与世界时间的关系

前期战斗规模很小（三人对几只妖兽），且经常发生在其他角色正在别处干活的时候。如果每次都切进独立战斗场景并冻结世界，会非常割裂。

**当前决定：分两档处理。**

| 战斗类型 | 处理方式 |
|---|---|
| 遭遇战（小队级） | 不切场景，就在世界里打，世界时间照常流逝，开打时自动暂停让玩家下令 |
| 战役（据点争夺、势力会战） | 进入独立战斗场景，世界时间冻结，战后按战斗规模统一扣除战略时间 |

这样既保留了"A 在打架时 B 还在采药"的同时性，又避免了后期大规模战役与世界模拟互相干扰。

自动结算属于第一档，直接在世界时间里推进并给出可溯源的结果。

## 7. 无人照看时世界如何运转

- 角色不在据点时，已分配的岗位与政策**持续自动执行**，产出照常按日结算。
- 修士的长期任务（闭关、外出探索、驻守）按 Tick 推进，完成或遇阻时通知玩家。
- 玩家只处理异常（遇袭、饥荒、叛离、任务受阻），不需要每天回来点一遍收获。

判定标准：玩家离开据点一个月再回来，据点应该是**正常运转且有积累**的状态，而不是停摆等着他回来按按钮。

## 8. 一天的完整推演（前期劳役阶段）

用这一天检验上面所有规则是否自洽。

| 时段 | 发生了什么 | 玩家在做什么决定 |
|---|---|---|
| 卯时 | 监工下达配额：木材 20、妖兽 3、武器 3 | **决定 1**：三人如何分工 |
| 辰巳 | 甲去林中伐木，乙丙结伴去猎妖兽 | 自动执行，玩家可加速 |
| 午时 | 乙丙遭遇第三只妖兽，比预想的强 → 自动暂停 | **决定 2**：硬拼、撤退，还是叫甲支援 |
| 未时 | 战斗结束，乙受轻伤。甲提前完成伐木 | **决定 3**：甲是去帮忙打铁，还是去探那处灵地 |
| 申时 | 武器只打了 2 件，配额眼看完不成 | **决定 4**：熬到黄昏赶工，还是接受扣粮换取时间 |
| 酉时 | 交差。缺 1 件武器，扣发部分口粮，怀疑度小幅上升 | 结果反馈 |
| 戌时 | 宵禁。守卫开始巡逻 | **决定 5**：今晚是否出门 |
| 亥时 | 甲潜出前往灵地，乙丙留在住处附近掩护 | **决定 6**：谁修炼、谁掩护、藏匿点放哪 |
| 子丑 | 甲修炼；乙拦下一名靠近的守卫闲聊 | 自动执行，怀疑度缓慢上升 |
| 寅时 | 巡逻队临时改道 → 自动暂停 | **决定 7**：立刻收手撤回，还是赌能练完这一段 |
| 卯时 | 新一天的配额下达，甲带伤且未休息，效率下降 | 昨夜的选择在今天产生代价 |

一天大约 **5–8 次真正重要的决定**，其余时间由角色自动完成。这个密度既不至于变成频繁暂停的微操，也不会让玩家觉得自己在看播片。

## 9. 三层循环

在上面的日循环之上，还有两层更长的循环。

### 日循环（分钟到小时级）

```
清晨领配额 → 分工 → 执行与突发 → 黄昏验收
→ 夜间隐匿行动 → 修为与风险同时积累 → 次日
```

### 中期循环（数十天）

```
省出的时间与私藏资源 → 修为积累 → 具备反抗或脱离的实力
→ 取得第一处据点 → 解锁领地经营 → 稳定的修炼条件
```

### 长期循环

```
领地供养修士 → 修士突破获得机制能力
→ 新能力开启更高层级的区域与对手 → 占领更高价值领地
→ 支撑更多修士与更高质量的突破
```

## 10. 循环必须成立的三个约束

- **不修炼**：打不过更强的对手，也进不了危险区域。
- **不扩张**：缺乏灵地、资源与人口，修炼质量与势力上限受限。
- **只堆人口**：凡人无法替代高阶修士，但能支撑经济、防务与低阶战争。

## 11. 未决问题

- [ ] 1 Tick = 15 分钟是否合适？砍一棵树、走到邻村、打一场遭遇战各需要多少 Tick，需要在原型里试出手感。
- [ ] 指令队列是否允许设置条件（"体力低于三成就回去休息"）？这会显著提升自动化程度，但也提高实现成本。
- [ ] 角色是否有自主性——没有指令时会自己找事做，还是原地待命？建议原地待命并触发暂停提示。
- [ ] 16x 速度下的战斗如何处理？是强制降速还是自动结算？
- [ ] 睡眠与体力如何建模？夜间修炼必然挤占睡眠，这个代价要在数值上表达出来。
- [ ] 多据点后，日结算的信息量如何控制，避免每天弹出一长串汇报？
