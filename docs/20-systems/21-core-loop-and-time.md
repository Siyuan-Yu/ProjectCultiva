# 核心循环与统一时间

> 状态：Tick／ActionClock 已冻结于 `33` v0.2；时间表权限待正式验证 | 优先级：P0 | 最后更新：2026-07-31
> 关联：`../30-tech/33-architecture-core-rules-freeze-v0.2.md`、ADR-0018、`35`
> **WorldTick = 世界唯一时间轴；ActionClock = 行动 Duration。** 禁止两套世界时间。

## 1. 这个系统解决什么问题

角色行动、修炼、领地生产、事件推进和战斗必须能换算到**同一条游戏时间**上。同时，时间本身要成为社会自由的表达：

> 低阶凡人没有属于自己的时间，高阶修士和势力掌控者拥有更多时间自由。

时间不是单纯的倒计时，而是角色在修仙社会中的自由程度。

## 2. 时间系统定位

游戏采用类似《环世界》的**时间表系统**。

- 时间表是社会规则，不是强制执行的死脚本。
- 不同身份拥有不同时间表，决定一天中哪些时段属于义务、哪些时段属于自由。
- 玩家前期的核心矛盾之一，是如何在被规定好的时间缝隙里挤出修炼与探索。

与 `2F-obligation-and-concealment.md` 的关系：配额决定"今天要交什么"，时间表决定"什么时候该在做什么"。二者共同构成前期压迫。

## 3. 时间表（Schedule）

### 3.1 形态

时间表按身份配置。例如劳役者：

- 早晨起床
- 白天工作
- 固定吃饭时间
- 固定休息时间
- 少量自由活动时间

**具体时间段通过配置表调整，不写死在文档或代码里。**

### 3.2 不同身份的时间表

| 身份 | 时间自由程度（方向） |
|---|---|
| 凡人劳役 | 最低；白天义务占比最高，自由时段极少 |
| 外门弟子 | 有固定功课与杂役，但开始出现修炼时段 |
| 内门弟子 | 义务减少，修炼与任务自主度上升 |
| 长老 | 大量自由时间，只需处理关键事务 |
| 宗主 | 最高；可制定他人时间安排 |

具体各身份时段表**待设计**。

### 3.3 时间表权限

| 阶段 | 玩家能做什么 |
|---|---|
| 前期（劳役／隐藏修士） | **只能查看**当前时间表。玩家是被管理者，没有修改规则的权力 |
| Demo 测试 | 可临时开放修改时间表，用于验证玩法，不代表正式前期权限 |
| 夺取第一据点后 | **获得修改时间表权限**：可调整居民工作、休息、娱乐等安排；影响生产、幸福度与人才成长 |
| 后期（多据点／宗门） | 可制定他人时间安排：凡人生产、弟子修炼、巡逻、研究等 |

时间管理本身成为势力成长的一部分：从"被时间表支配"到"给别人排时间表"。

## 4. 指令模型：下达意图，角色自动执行

- 玩家下达的是**意图**（去砍那片树、去打那三只妖兽、留在这里修炼），角色自动寻路、执行、汇报。
- **三名角色可以完全分头行动**，各自持有独立的指令队列。
- 指令可以随时追加、插队、取消、改派，一天之内没有指令次数上限。
- 玩家不需要逐帧操作，也不应该因为手速获得优势。

### 推论：玩家真正在做的决策是分配稀缺时间

既然过程自动完成，玩家的乐趣就必须来自**取舍**：这个人今天去干活还是去掩护？省下的两个时辰拿去修炼还是去打听消息？

### 抽象层随规模上移

| 规模 | 玩家操作粒度 |
|---|---|
| 3 人 | 逐个下达具体指令 |
| 10 人上下 | 设定岗位、时间表与优先级，只对关键角色单独下令 |
| 30 人以上 + 多据点 | 设定政策与方针，只处理异常和重大抉择 |

## 5. 角色控制方式（待 Demo 验证）

当前设计需要通过 Demo 验证，暂定支持：

### 5.1 手动控制

玩家直接控制角色：

- 移动
- 战斗
- 对话
- 探索

### 5.2 自动模式

角色可以选择：

- 自动跟随主角
- 自动按照时间表行动

**第一阶段不设计复杂自主 AI。**

没有玩家命令时：角色**默认待机**，并应提示玩家（避免时间空转而不自知）。

## 6. 角色行为优先级

从高到低：

1. **玩家直接命令**（最高）
2. **紧急事件**（战斗、危险）
3. **时间表行为**
4. **待机**

### 示例

角色正在工作。突然妖兽攻击。

流程：停止工作 → 进入战斗。

即使此时到了吃饭或工作时间，也不会强制切换回时间表。

战斗结束后，再根据当前时间与主管规则判断是否产生影响（例如是否耽误交差、是否引起主管愤怒）。

## 7. 时间粒度

### 逻辑层

- 最小时间单位 **1 Tick = 15 游戏分钟**。
- 一个游戏日 = **96 Tick**。
- 逻辑层只认 Tick，不认真实秒数。所有耗时都以 Tick 表示，便于存档、回放和可溯源。

### 表现层

玩家看到的是时辰、时段与时间表槽位，不是 Tick 计数。

| 时段 | 时辰 | Tick 区间 | 前期劳役的典型含义 |
|---|---|---|---|
| 清晨 | 卯 | 20–28 | 起床／点名，领取当日任务 |
| 上午 | 辰巳 | 28–44 | 工作时段 |
| 正午 | 午 | 44–52 | 工作或固定吃饭／休息 |
| 下午 | 未申 | 52–68 | 工作时段 |
| 黄昏 | 酉 | 68–76 | 交差验收，分发口粮 |
| 入夜 | 戌亥 | 76–88 | 宵禁开始，少量自由或休息 |
| 深夜 | 子丑寅 | 88–20 | 巡逻稀疏，暗面行动主时段 |

具体时段划分以配置表为准，上表只是前期体验的示意骨架。

### 时间流速

**暂定：现实约 5～10 分钟 = 游戏一天。**

支持：

- 暂停
- 2 倍速
- 5 倍速

时间尺度后续通过 Demo 调整。逻辑层仍以 Tick 推进；倍速只改变 Tick 流逝相对现实时间的速度。

高倍速时**不降低事件触发概率**，改为提高自动暂停的灵敏度。玩家快进是为了跳过无事发生的时段，不是为了跳过内容。

## 8. 每 Tick 的结算顺序

顺序固定，保证同样的存档与同样的操作必然得到同样的结果。

```
1. 推进时间        Tick +1，更新时辰、时段、日期、时间表槽位
2. 优先级裁决      玩家命令 / 紧急事件 / 时间表 / 待机
3. 角色行动        移动、采集、制作、修炼、掩护的进度累积
4. 环境与生产      资源点刷新、建造进度、领地产出累积
5. 状态变化        体力、饥饿、伤势、修为、主管相关状态
6. 判定与事件      任务验收、遭遇判定、巡逻检查、突破条件检查
7. 中断检查        判断是否需要自动暂停并提示玩家
```

领地产出**按 Tick 累积、按日结算**。玩家看到的是每日汇总，不是每 15 分钟弹一次收成。

## 9. 自动暂停

**必须自动暂停：**

- 遭遇敌对单位，或战斗即将开始
- 主管愤怒跨越阈值，或角色即将被撞见／被发现
- 修炼完成、突破的关键节点
- 角色重伤、濒死、中毒等严重状态
- 重要事件或抉择触发
- 全部角色的指令队列清空且无事可做（默认待机时）

**只通知不暂停：**

- 采集、制作、建造完成
- 每日产出结算
- 普通 NPC 对话请求

两类归属应当可由玩家在设置里调整。

## 10. 战斗与世界时间的关系

> **2026-08-21 冻结修订**（[ADR-0023](../40-process/43-decisions/ADR-0023-manual-encounter-freezes-worldtick.md)）。旧「战斗期间世界时间照常流逝／甲交战乙可别处劳作」已废弃。

战略遭遇采用全战式 Modal：

```text
Strategic World → BattleOffer → 冻结 WorldTick
  → AutoResolve 或 Manual Encounter → PostBattle → Resolve
  → 恢复开战前 pause／time scale
```

- 全世界仍只有一个 **WorldTick**（ADR-0018）。  
- `BattleOffer` 产生后立即冻结 WorldTick；Manual／PostBattle 期间不推进。  
- 手动战现实时长 **不**映射为战略 Tick 消耗；AutoResolve 亦不额外推进 Tick。  
- 手动战期间 ActiveMap 锁定遭遇图；禁止切其他 LocalMap、禁止战略派兵离开；大地图可只读。  
- **战术层**仍可 RTS＋暂停下令（只影响遭遇表现，不推动 WorldTick）。  
- 同 Tick 多个接战入队串行 Resolve，不得并行两个 Manual。  

节点／据点内的日常冲突若未走战略 BattleOffer，仍可按 LocalMap 即时战斗处理；一旦升级为战略 `BattleOffer`，适用本条。

**待确定：** 大规模战争／攻城是否另开 Persistent 战场规则（不在 ADR-0023 范围）。

## 11. 无人照看时世界如何运转

- 角色不在据点时，已分配的岗位、时间表与政策**持续自动执行**，产出照常按日结算。
- 修士的长期任务（闭关、外出探索、驻守）按 Tick 推进，完成或遇阻时通知玩家。
- 玩家只处理异常（遇袭、饥荒、叛离、任务受阻），不需要每天回来点一遍收获。

## 12. 一天的完整推演（前期劳役阶段）

| 时段 | 发生了什么 | 玩家在做什么决定 |
|---|---|---|
| 卯时 | 主管／监工下达当日任务 | **决定 1**：三人如何分工 |
| 辰巳 | 甲伐木，乙丙猎妖兽 | 自动执行，玩家可加速 |
| 午时 | 乙丙遭遇更强妖兽 → 自动暂停 | **决定 2**：硬拼、撤退，还是叫甲支援 |
| 未时 | 战斗结束。甲提前完成伐木 | **决定 3**：甲去赶工，还是去探灵地 |
| 申时 | 任务眼看完不成 | **决定 4**：熬到黄昏赶工，还是接受惩罚换时间 |
| 酉时 | 交差。部分未完成，主管愤怒上升 | 结果反馈 |
| 戌时 | 宵禁。少量自由时段开始 | **决定 5**：今晚是否出门 |
| 亥时 | 甲潜出修炼，乙丙掩护 | **决定 6**：谁修炼、谁掩护 |
| 子丑 | 甲修炼；乙拦下靠近的守卫 | 自动执行 |
| 寅时 | 巡逻改道 → 自动暂停 | **决定 7**：收手还是赌完这一段 |
| 卯时 | 新一天任务下达；昨夜代价显现 | 昨夜选择产生今日后果 |

**注意：玩家每天可下达的命令次数没有任何上限。** 上表统计的是真正影响走向的重要决定，一天大约 **5–8 次**，这是节奏目标，不是操作限制。

## 13. 三层循环

### 日循环

```
清晨领任务 → 按时间表工作 → 执行与突发 → 黄昏验收
→ 夜间隐匿行动 → 修为与风险同时积累 → 次日
```

### 中期循环

```
省出的自由时间与私藏资源 → 修为积累 → 具备反抗或脱离的实力
→ 取得第一处据点 → 解锁领地经营与时间表制定权
```

### 长期循环

```
领地供养修士 → 修士突破获得机制能力
→ 新能力开启更高层级区域 → 占领更高价值领地
→ 支撑更多修士与更高质量的突破
```

## 14. 循环必须成立的三个约束

- **不修炼**：打不过更强的对手，也进不了危险区域。
- **不扩张**：缺乏灵地、资源与人口，修炼质量与势力上限受限。
- **只堆人口**：凡人无法替代高阶修士，但能支撑经济、防务与低阶战争。
