## 1. 属性系统与 Modifier 管道（P0）— 已冻结

### 1.1 统一计算

所有最终属性计算遵循：

```
Final Value =
  Base Value
  + Fixed Modifiers          （固定加算）
  + Percentage Modifiers      （百分比加成，基数为 Base + Fixed 的结果，除非系统文档另有规定）
  + Special Rules             （极少数硬规则；必须登记来源，禁止隐式改 Final）
```

### 1.2 管道强制

- 所有影响属性的来源**必须**通过 Modifier 管道接入。
- Modifier **必须记录来源**（来源类型 + 来源实例标识）。
- UI / 调试必须能展开完整计算链（数值可溯源）。

示例：

| 项 | 值 |
|---|---|
| 攻击力 Base | 100 |
| 火灵根 | +20%（Percentage） |
| 火系功法 | +30%（Percentage） |
| 环境 | +10%（Percentage） |
| Final | 可追溯到上述来源 |

### 1.3 来源类型（SourceKind）

至少支持：

| SourceKind | 说明 |
|---|---|
| Talent | 天赋 |
| SpiritRoot | 灵根 |
| Manual | 功法 |
| Skill | 技能／术法 |
| Realm | 境界 |
| Environment | 环境（灵地、属性地块等） |
| Building | 建筑 |
| StatusEffect | 状态效果 |
| Event | 事件 |

### 1.4 禁止写法

禁止系统直接修改最终属性：

```text
❌ attack += 20
✅ AddModifier(source, value, kind)
```

移除来源时，只能撤掉该来源下的 Modifier，不得「倒算」硬改 Final。

### 1.5 术语边界

- 配置内容中的「词条」（glossary 中的 `Modifier` / 可组合效果）是**内容数据**。
- 进入运行时后，词条效果必须落到本管道的 **AttributeModifier** 上。
- 实现与文档中优先写 **AttributeModifier**，避免与「词条」混称。

### 1.6 仍待展开（不阻断冻结）

- [ ] 百分比是「对 Base」还是「对 Base+Fixed」的最终定稿公式表
- [ ] Special Rules 的白名单与审批流程
- [ ] 属性枚举与配置表字段（见后续 `2C` 展开）

系统文档入口：后续以 `2C-attributes-and-modifier-pipeline.md` 展开数据结构；**形状以本节为准**。

## 2. 时间系统与 Tick 模型（P0）— 已冻结

### 2.1 双层时间

| 层 | 职责 |
|---|---|
| 逻辑层 | **Tick** 推进；所有模拟只认 Tick |
| 表现层 | 玩家看到的游戏小时／分钟；`GameClock` 负责显示与倍速／暂停映射 |

### 2.2 基础换算

| 规则 | 值 |
|---|---|
| 1 Tick | 15 游戏分钟 |
| 1 游戏日 | **96 Tick** |

### 2.3 统一依赖

下列系统**统一依赖 Tick**，禁止各自用 `deltaTime`／独立计时器做逻辑结算：

- NPC 行动
- 修炼增长
- 资源生产
- 事件触发
- 世界模拟
- 突破窗口

### 2.4 GameClock

- 保留为**表现层**时间显示与玩家倍速／暂停入口。
- 正式架构中：表现层时钟驱动「推进了多少 Tick」，逻辑层只消费 Tick。
- Demo 中的连续分钟推进，迁移时映射为 Tick，**不改变「暂停停进度、倍速加快进度」的语义**。

### 2.5 仍待展开

- [ ] 同一 Tick 内各系统结算顺序（调度表）
- [ ] 暂停时允许下达哪些指令（见 `21`）
- [ ] 存档存 Tick 还是存绝对游戏分钟（建议存 Tick + 种子）

## 3. 实体模拟分层规则（P0）— 已冻结

采用**四层模拟**。规模扩大靠抽象，不靠等比例微操。

### 3.1 第一层：玩家控制修士（全模拟）

- **完全模拟**：位置、属性、行动、战斗、修炼、技能。
- **数量目标**：约 **30～50** 人（长期养成上限方向）。
- 玩家可直接下令；高精度指令队列。

### 3.2 第二层：关键 NPC（全模拟）

例如：主管、商人、宗门关键人物、重要敌人。

拥有：属性、日程、关系、成长、事件记录。

与第一层同属「实体」精度，但**默认不可由玩家直接当作小队成员微操**（可对话、可成为目标、可进事件）。

### 3.3 第三层：普通修士群体（抽象模拟）

- **不模拟每个人的位置**。
- 只计算：数量、境界分布、成长概率、势力变化等聚合量。
- 需要出场时，可临时生成或升级为第二层实体（规则待 `27` 展开）。

### 3.4 第四层：凡人群体（统计模拟）

一个村庄**不是** 2000 个独立 NPC。

群体数据示例：人口、粮食、幸福度、劳动力、天赋池。

**只有被玩家关注（或剧情／系统指定）的人**才升级为第二层实体。

### 3.5 边界纪律

| 允许 | 禁止 |
|---|---|
| 关注升级：群体 → 关键实体 | 默认把全村做成可点选个体 |
| 关键实体降级回群体（离开视野／死亡归档等，细则待定） | 第三／四层偷偷做全位置 AI「假装群体」 |

## 4. 境界系统：炼气期能力定义（P1）— 方向已冻结

### 4.1 总则

**境界提升必须带来玩法变化**，不是单纯加属性。

### 4.2 感应境

- 开局核心角色默认境界；能感受天地灵气、做基础吸收与修炼准备。
- **不能**修炼正式功法；**不能**真正运转灵力／使用修士战斗能力。
- 相对「炼气」仍属入道前阶段；与「毫无感应的普通凡人」不同（普通凡人主要在第四层统计）。

### 4.3 炼气期（首次成为真正修士）

解锁（已冻结方向）：

| # | 能力 | 用途 |
|---|---|---|
| 1 | **灵力池** | 技能释放、护体、防御等消耗与缓冲 |
| 2 | **功法修炼** | 可装备／运转正式功法 |
| 3 | **基础术法** | 学习并释放修仙技能 |
| 4 | **灵气感知（强化档）** | 更易发现灵地、天材地宝、特殊区域（与神识／经历配合；细则见 `22`／`2B`） |

### 4.4 明确暂不确定

- 飞行、踏空、空间通道等高级能力**不在炼气冻结范围**。
- 炼气基础术法的**具体清单与强度**仍待定（总览跨系统问题）。

## 5. 第一次突破事件规则（P1）— 方向已冻结

### 5.1 总则

- 突破**不能**只是「点击按钮增加境界」。
- **大境界突破必须是事件**（有准备、有过程、有结果）。

### 5.2 基本流程

**准备阶段**

- 修为达到要求
- 寻找合适地点
- 准备资源（与环境、功法、状态相关）

**突破阶段**

可产生：天地异象、风险、外界干扰等事件内容。

**结果（方向）**

- 成功
- 失败
- 特殊结果（与 `25` 四类结果对齐展开：普通／完美／瑕疵／失败反噬等）

### 5.3 第一次凡人侧 → 炼气

- **感应境 → 炼气** 作为第一章核心事件（见 `2G`）。
- 是垂直切片下一阶段的玩法重点，**不是** Demo 继续堆功能。

### 5.4 必须继续细化（未冻结细则）

- [ ] 突破地点影响
- [ ] 护法机制
- [ ] 风险来源
- [ ] 失败后果
- [ ] 异象暴露与隐匿三层系统的联动

## 6. 隐匿／暴露系统规则（P1）— 已冻结分层

### 6.1 明确：不合并成单一数值

分三层，互相关联，**禁止**并成一个「暴露条」打天下。

### 6.2 个人隐匿风险（PersonalConcealmentRisk）

- **描述**：玩家偷偷修炼是否容易被察觉（自身行为风险）。
- **影响因子方向**：修炼地点、时间（昼夜）、隐藏手段（如敛息草）等。
- Demo 中的 `ExposureRisk` 语义映射到本层；正式实现改名对齐术语表。

### 6.3 NPC 怀疑值（Suspicion）

- **描述**：**具体 NPC** 是否怀疑玩家异常（例：主管觉得最近状态不对）。
- **影响方向**：巡查、对话、调查等。
- 按 NPC 实例记账，不是全局一条。

### 6.4 势力关系／敌意（FactionAttitude / Hostility）

- **描述**：整个势力对玩家的态度（例：宗门已知反抗）。
- **影响方向**：追杀、招募、势力级事件等。

### 6.5 关联方式（方向）

```
个人隐匿风险 ──触发／加速──→ 附近 NPC 怀疑值
NPC 怀疑值累计／事件 ──上报／扩散──→ 势力敌意
势力敌意 ──改变──→ 巡查强度、事件池、对话选项
```

具体公式与阈值**待定**；分层形状**已冻结**。

### 6.6 与 Demo 的关系

Demo 仅显示个人暴露与主管愤怒数值、无真实惩罚——该语义保留为「只显示」的原型验证；正式惩罚与三层联动在实现期按本节接入，不回退为单数值。
